The problem

A beginner learning to code today faces a strange trap. The AI will write anything they ask for — so they never struggle, never trace code in their head, and never build the one skill that now matters most: looking at code someone else wrote and knowing whether to trust it. They can generate endlessly and judge nothing. That's not a developer; that's a passenger.

The idea

The Shoddy Apprenticeship flips the modern learning loop back into the right order. The learner is the apprentice. The teacher is the Craftsman — an AI given strict standing instructions to behave like a seasoned tradesperson at a bench, never like a chatbot that hands out answers. The workbench is Shoddy, a small, purely functional BASIC built for exactly this job: readable line-one syntax, no framework noise, no Stack Overflow escape hatch, and a difficulty curve we fully control because we own the language.

One principle runs through everything: understanding must be earned before it is automated. The apprentice writes every line by hand first, so that by the time they're allowed to prompt the Craftsman for code, they can judge what comes back. Validation is the skill; generation is the reward.

The whole arc in one sentence: write it yourself → read what others wrote → guide the Craftsman → validate the Craftsman → own the outcome.

How it works

Five phases, each shifting who holds the pen:

  1. Manual Craft — the apprentice writes 100% of the code. The Craftsman demonstrates on different problems and coaches with questions, never answers. (Seven lessons, fully written.)
  2. Reading the Craft — the apprentice critiques code they didn't write, including deliberately flawed code. Training the eye.
  3. Guided Generation — the apprentice writes the spec, the Craftsman drafts half-finished code, the apprentice completes and verifies it.
  4. Prompt & Validate — the modern working loop: the apprentice prompts for whole functions, then validates rigorously with tests the Craftsman didn't write.
  5. Ownership — multi-part projects where the apprentice directs, reviews, and takes full accountability for code they didn't type.

Every lesson follows the same eight-step ritual: demonstration, challenge, predict-before-you-run (a hard gate — no running code blind, ever), productive struggle, run & validate, critique, reflection, and one durable takeaway. The Craftsman operates under a contract it never breaks: no unexplained solutions, no code-writing in Phases 1–2, never “wrong” — always “not yet.”

The design isn't invented from scratch. It's the Cognitive Apprenticeship model — modeling, coaching, scaffolding that fades as skill grows — plus two well-established levers: productive struggle (effort makes learning stick) and worked-example fading. What's new is aiming all of it at the skill the AI era actually demands.

The investment

WhatHow much
WhoA curious beginner — the bar is a sharp 8th grader with zero programming experience. Every term is defined in plain English on first use. Works equally for an adult starting over.
SetupAbout an hour, once: a free toolchain — VS Code, the Shoddy extension, and the mill (the compiler). One system prompt pasted into any capable AI chat account turns it into the Craftsman. No paid courseware.
TimeLessons run roughly 45–90 minutes each. Phase 1 (seven lessons) is about 10–12 hours — a month at 2–3 sessions a week. The full fifteen-module arc through the capstone is on the order of 35–45 hours, a comfortable season of steady practice. (Self-paced; these are working estimates — final pacing is an open design item.)
EffortThe real price — see below.
The real price The apprentice must accept struggle as the method. They will write a prediction before every single run. They will sit with an error message instead of being rescued. They will explain their reasoning out loud. The Craftsman is engineered to withhold the answer when the apprentice is one step from finding it — because that step is where the learning is stored. An apprentice (or parent) shopping for frictionless progress should look elsewhere; this is deliberately the opposite.

The expected results

By the end of Phase 1, the apprentice can write, run, and debug real programs by hand: decisions, repetition without loops, their own functions, recursion, and Map/Filter/Fold — and they've internalized the course's two standing habits: predict before you run and the bugs live on the boundaries.

By the end of Phase 5, the apprentice works the way a modern developer actually works: they can break a problem down, write an unambiguous spec, direct an AI to draft code, read the result critically, write their own tests to catch the plausible-but-wrong, and take ownership of the final product. The durable outcome isn't Shoddy fluency — it's transferable judgment: the difference between someone who can ask an AI for code and someone who can be responsible for it.

That judgment is the whole point. Generation is cheap now. Trust is not.
