The Shoddy Apprenticeship · Lesson 1 of 7

Hello, Shoddy

Make the computer say something, run your first program, and start a habit you will keep forever.

Durable takeaway: A program does exactly what you told it — not what you meant. The gap between those two is where all of programming lives.
Phase1 — Manual Craft (the apprentice writes 100% of the code; the Craftsman writes no Shoddy)
PrerequisitesNone. This is the very first lesson.
New Shoddy conceptsDef Main() (where a program starts); Print(...) (show something on screen); Rem (a note for humans); the run cycle (▶ / Ctrl+Shift+B)
Thinking skillMaking a guess about what will happen before you run — and caring whether you were right
Time20–30 minutes

Step 1

Craftsman’s Demonstration

The Craftsman shows a finished tiny program and talks through every piece. The apprentice just watches.

The Craftsman speaks

“Watch. I want the computer to say hello. Here is the whole program:”

Def Main()
    Print("HELLO, WORLD")

The Craftsman speaks

“Two lines, and every word matters.

Def Main() is the starting line. Every Shoddy program begins running at a place called Main. Think of it like the front door of a house — the computer always walks in through Main. Don’t worry about why it’s spelled Def yet; for now it just means ‘here is where things start.’

Print(&quot;HELLO, WORLD&quot;) is a command. Print means ‘show this on the screen.’ The thing in the quote marks — &quot;HELLO, WORLD&quot; — is called a text string: it’s just a run of characters, and the double-quotes tell Shoddy ‘treat everything between us as plain text, exactly as written.’

Notice the second line is pushed in from the left — it’s indented. In Shoddy, that indenting is how the computer knows Print belongs inside Main. Line things up carefully; the spacing isn’t decoration, it’s meaning.”

Step 2

The Challenge

Now the apprentice holds the pen.

Make a new file called hello.shoddy. Write a program that, when you run it, prints these two lines exactly:

MY NAME IS <your name>
I AM LEARNING SHODDY

(Put your own name where it says <your name>.)

Hints you’re allowed to use:

  • You’ll need Def Main() on the first line.
  • You’ll need two Print lines, both indented underneath.
  • Do not run it yet — Step 3 comes first.
Step 3

Predict Before You Run

The single most important habit in this whole course starts right here, in Lesson 1.

Before you press the run button, write down (on paper, or as a Rem note at the bottom of your file — a Rem line is a note for humans that Shoddy ignores):

  1. Exactly what two lines do you expect to see?
  2. What do you think happens if you forget the quote marks around your name? (Just guess — you’ll test it later.)
GateWrite your prediction now, before moving on.
Step 4

Productive Struggle

The Craftsman coaches with questions. Here is the script it follows.

If nothing happens when you run it, or you can’t find the run button:

  • “Look for a ▶ triangle at the top-right of the editor, or press Ctrl+Shift+B. Where does the text appear — is there a panel at the bottom of the screen?”

If you get ERROR (line N): ...:

  • “Shoddy is telling you the exact line it got confused on. Go to line N. Read the message out loud. Is a quote mark missing? Is a line indented differently from the others?”

If only one line printed:

  • “How many Print commands does the computer need to show two lines? Count your Print lines. Are both of them indented the same amount so both live inside Main?”

If the apprentice asks ‘why is it Main and not Start?’:

  • “Good question — because that’s the word Shoddy’s makers chose for the front door. You don’t have to agree with the name; you just have to use it. Later you’ll name your own commands whatever you like.”
Step 5

Run & Validate

Press ▶ (or Ctrl+Shift+B). Look at the panel at the bottom (the terminal).

  • Did the two lines match your Step 3 prediction, exactly? Same words, same order?
  • Now run your experiment: remove the quote marks around your name and run again. What happened? (You’ll likely get ERROR (line N).) This is good. You just learned what quotes are for: without them, Shoddy tries to understand your name as a command instead of as text.
  • Put the quotes back and confirm it works again.

A correct solution looks like this — but only compare it to yours after yours runs:

Def Main()
    Print("MY NAME IS SAM")
    Print("I AM LEARNING SHODDY")
Step 6

Craftsman’s Critique

A craftsman inspects the joinery — naming what’s sound, what’s fragile, and why.

SoundWhat’s sound. “You indented both Print lines the same amount. That’s not a small thing — indentation is how Shoddy knows what belongs together, and you got it right on your first program.”
FragileWhat to watch. “When your name lost its quotes and the program broke — did you read the error message, or just panic and put them back? Reading the message before fixing is a habit worth building now, while the programs are tiny.”
Step 7

Reflection Retro

The apprentice does the talking; the Craftsman only prompts.

  1. What surprised you — the working version, or the broken one?
  2. The error message pointed at a specific line. Did that make the problem easier or scarier? Why?
  3. If a friend’s program printed nothing at all, what’s the first thing you’d tell them to check?
Step 8

Critical-Thinking Takeaway

One durable principle.

PrincipleThe computer does exactly what you wrote, not what you meant. Quotes, indentation, spelling — the computer takes them literally. That’s not the computer being difficult; it’s the one thing that makes programming learnable: the rules never change on you.
