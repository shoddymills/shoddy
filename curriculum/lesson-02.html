Values & Names

Store numbers and text, give them names, and join text together — then keep track of what each name holds.

Durable takeaway: A name is a label on a box. To understand a program, you track what’s in each box — because the computer never guesses; it only ever reads exactly what you put there.
Phase1 — Manual Craft (the apprentice writes 100% of the code; the Craftsman writes no Shoddy)
PrerequisitesLesson 1 (Print, Main, the run cycle)
New Shoddy conceptsLet name = value (give a value a name); the three basic value kinds — Number, String (text), Boolean (True/False); & to join text; Str(...) to turn a number into text
Thinking skillKeeping track, in your head, of what each name currently holds

Step 1

Craftsman’s Demonstration

The Craftsman models the idea on its own example.

The Craftsman speaks

“So far we’ve only printed text we typed on the spot. Now let’s store things and give them names. Watch:”

Def Main()
    Let age = 13
    Let name = "ALEX"
    Let isStudent = True
    Print(name)
    Print(age)
    Print(isStudent)

The Craftsman speaks

“Let age = 13 creates a name, age, and puts the value 13 in it. From now on, wherever I write age, Shoddy reads it as 13. A name like this is sometimes called a variable, but I like to think of it as a labeled box.

Look at the three kinds of value I stored:

  • 13 is a Number. Numbers are for counting and math. No quotes.
  • &quot;ALEX&quot; is a String — that’s the word for text. It gets quotes.
  • True is a Boolean — a yes/no value. The only two Booleans are True and False. No quotes, and — this matters — a Boolean is never a number. True is not 1.

The Craftsman speaks

One Shoddy rule to burn in now: once you Let a name, its value never changes. age is 13 forever in this program. If I need 14, I make a new box. This feels strict, but it means you can always trust what a name holds — it can’t be quietly changed somewhere else.”

A second demonstration — joining text with &

Def Main()
    Let name = "ALEX"
    Let age = 13
    Print("HELLO, " & name)
    Print(name & " IS " & Str(age) & " YEARS OLD")

The Craftsman speaks

“The & symbol glues text together. &quot;HELLO, &quot; & name becomes &quot;HELLO, ALEX&quot;. Watch the space I left inside the quotes after the comma — without it you’d get HELLO,ALEX jammed together. The computer won’t add spaces you didn’t ask for.

And notice Str(age). age is a number, but & only glues text. Str means ‘turn this number into text so I can glue it.’ If you forget Str and try to glue a number directly, Shoddy will complain — and now you’ll know why.”

Step 2

The Challenge

Now the apprentice holds the pen.

Make a file card.shoddy. Store these four facts as named boxes, then print a little ‘ID card.’ Use your own real values:

  • a String for a first name
  • a Number for a birth year
  • a Number for the current year
  • a Boolean for whether you like pizza

Then print exactly these three lines (filled in with your values):

NAME: <first name>
AGE THIS YEAR: <current year minus birth year>
LIKES PIZZA: <True or False>

The middle line means you must do the subtraction inside the program — don’t just type the answer. (You can write math like currentYear - birthYear directly.)

Step 3

Predict Before You Run

Say what you think will happen, first.

Write down before running:

  1. For each of the three printed lines, what exact text do you expect?
  2. In the AGE line, you’ll need to glue text and a number. Which piece needs Str(...) around it, and why?
  3. What would happen if you wrote Print(&quot;AGE THIS YEAR: &quot; & currentYear - birthYear) — do you think the subtraction happens first, or the gluing? (Guess now; test later.)
Step 4

Productive Struggle

Questions, never answers.

If you get an error on the AGE line:

  • “You’re gluing text and a number. & only glues text. What has to happen to the number first? Look back at how the demonstration handled Str(age).”

If the AGE math came out wrong (a huge number, or text stuck together):

  • “Read the line slowly. Is the computer doing the subtraction, or is it gluing before subtracting? Try putting parentheses around the math: Str(currentYear - birthYear). Why might that help?”

If LIKES PIZZA printed something you didn’t expect:

  • “What are the only two values a Boolean can be? Did you accidentally put quotes around True, turning it into the text &quot;True&quot; instead of the yes/no value True? Does it matter here? When would it matter?”

If you tried to change a box’s value (a second Let age = ...):

  • “Shoddy won’t let a name be set twice — a box keeps its value for life. If you need a different value, what could you name the new box instead?”
Step 5

Run & Validate

Execute, then compare to your prediction.

Run it. Check each line against your prediction.

  • The AGE line is the real test. If your age is right, you handled Str and the math order correctly. If it’s a giant number or mashed-together text, revisit the order: gluing vs. subtracting.
  • Try the experiment from Step 3: remove the parentheses around the subtraction and see what breaks. Understanding why it breaks is the lesson.

A correct shape (compare only after yours runs):

Def Main()
    Let firstName = "SAM"
    Let birthYear = 2012
    Let currentYear = 2026
    Let likesPizza = True
    Print("NAME: " & firstName)
    Print("AGE THIS YEAR: " & Str(currentYear - birthYear))
    Print("LIKES PIZZA: " & Str(likesPizza))
Step 6

Craftsman’s Critique

A craftsman inspects the joinery.

SoundWhat’s sound. “You did the subtraction in the code, not in your head. That means if you change the birth year, the age updates itself. Code that recomputes instead of hard-coding the answer is code you can trust as it grows.”
FragileWhat to watch. “Your spaces inside the quotes — &quot;NAME: &quot; with a space after the colon. Beginners forget those constantly and then wonder why the output looks cramped. The computer prints exactly your spaces, no more, no less.”
Step 7

Reflection Retro

The apprentice does the talking.

  1. Explain, in your own words, why Str(age) was necessary. Pretend you’re teaching it to someone in the grade below you.
  2. Shoddy wouldn’t let you change a box once it was set. Did that feel annoying, helpful, or both? Can you imagine a bug that rule prevents?
  3. Which was trickier: storing the values, or gluing them together for printing? Why?
Step 8

Critical-Thinking Takeaway

One durable principle.

PrincipleA name is a label on a box, and in Shoddy the box never changes. To read any program, walk down it line by line and keep a running list of what’s in each box. The computer does exactly that — no more, no less — and so should you.
