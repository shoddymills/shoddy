Words That Take Words

Lambdas and Map / Filter / Fold — separating what to do from what to do it to.

Durable takeaway: The most powerful move in programming is handing a function to another function. Once you can say ‘do THIS to every item,’ you can describe almost any list job in a single, readable line — and you’ve learned to think in terms of the operation itself, separate from the data.

Step 1

Craftsman’s Demonstration

The Craftsman models the idea on its own example.

The Craftsman speaks

“Back in Lesson 4 you wrote Fn(n) => Print(n) and I said ‘don’t worry about it yet.’ Now’s the time. Fn(n) => Print(n) is a lambda — a small function with no name, written right where you need it. Read Fn(n) => n * 2 as: ‘given something I’ll call n, give back n * 2.’

Here’s the big idea: in Shoddy, a function is a value, just like a number or a string. That means you can hand a function to another function. Watch the three tools that make this shine:”

Def Main()
    Let nums = { 1, 2, 3, 4, 5 }
    Print(Map(nums, Fn(n) => n * 2))
    Print(Filter(nums, Fn(n) => n > 2))
    Print(Fold(nums, 0, Fn(total, n) => total + n))

The Craftsman speaks

“Three tools, each takes a list and a function:

  • Map — ‘do THIS to every item, give me the new list.’ Map(nums, Fn(n) => n * 2) doubles every number: { 2, 4, 6, 8, 10 }. The list stays the same size; each item is transformed.
  • Filter — ‘keep only the items where THIS is true.’ Filter(nums, Fn(n) => n > 2) keeps { 3, 4, 5 }. The list gets shorter; items are kept or dropped.
  • Fold — ‘combine the whole list into one answer.’ Fold(nums, 0, ...) starts at 0 and adds each number in turn, giving 15. This is exactly the summing you did by hand with recursion in Lesson 6 — Fold is that pattern, packaged. Read it as: ‘start at 0; for each n, the new total is total + n.’

The Craftsman speaks

“The magic is: what to do is now separate from what to do it to. The list is the data; the lambda is the action. Swap the lambda, get a completely different result — same tool. That separation is the most valuable idea in this entire phase.”

Step 2

The Challenge

Now the apprentice holds the pen.

Make a file scores.shoddy. Start with this list of test scores:

Let scores = { 55, 90, 72, 88, 40, 100 }

In Main, produce and print three things, each in one line using Map, Filter, or Fold:

  1. Every score with 5 points added (a curve). (Which tool transforms every item?)
  2. Only the passing scores — 60 or above. (Which tool keeps some items?)
  3. The total of all the original scores added together. (Which tool combines into one answer?)

You’ll write a small lambda for each.

Step 3

Predict Before You Run

Say what you think will happen, first.

Write down first:

  1. For the curve (+5), what exact list do you expect?
  2. For the passing filter (≥ 60), which scores survive? Watch the boundary — is exactly 60 in or out, based on how you’ll write it?
  3. For the total, add the six original numbers by hand. What should Fold give you?
  4. Which tool did you choose for each task, and why? Say it before you write it.
Step 4

Productive Struggle

Questions, never answers.

If you’re not sure which tool fits a task:

  • “Ask one question per task: does the result have the same number of items (that’s Map), fewer items (that’s Filter), or is it one single answer (that’s Fold)? Match the shape of the answer to the tool.”

If your lambda has a syntax error:

  • “Check the shape: Fn(n) => something-using-n. Did you name the item after Fn(, and put => before the work? For Fold, the lambda takes two things: the running total and the next item — Fn(total, n) => ....”

If the passing filter included or excluded 60 wrongly:

  • “Lesson 3’s boundary again — it never stops mattering. Does ‘passing is 60 or above’ mean > 60 or >= 60? Which did you write?”

If Fold gave a strange answer:

  • “Fold needs a starting value — the second thing you pass it. For adding, what should you start from so it doesn’t change the total? What would starting from the wrong number do?”

If the apprentice asks ‘why not just use recursion from Lesson 6?’:

  • “You could — Fold is that recursion, done for you. But which reads more clearly to the next person: five lines of recursion, or Fold(scores, 0, +)? When is it worth writing the recursion by hand, and when should you reach for the packaged tool?”
Step 5

Run & Validate

Execute, then compare to your prediction.

Run it. Compare each line to your prediction:

  • Curve: same six items, each 5 higher? If the list got shorter, you used Filter by mistake — the shape of the wrong answer tells you which tool slipped in.
  • Passing: did exactly the right scores survive, including the correct call on 60?
  • Total: matches your hand-addition? If it’s off by the first number, your Fold starting value might be wrong.

A correct shape (compare after yours runs):

Def Main()
    Let scores = { 55, 90, 72, 88, 40, 100 }
    Print(Map(scores, Fn(n) => n + 5))
    Print(Filter(scores, Fn(n) => n >= 60))
    Print(Fold(scores, 0, Fn(total, n) => total + n))
AheadA taste of what’s ahead: Shoddy lets you write that sum even more briefly as Fold(scores, 0, +), handing the + operation itself in as the function. You don’t need that yet — but notice how far you’ve come: you’re now handing operations around as if they were values.
Step 6

Craftsman’s Critique

A craftsman inspects the joinery.

SoundSound. “You matched each task to the right tool by thinking about the shape of the answer — same size, fewer, or one. That’s the correct instinct, and it will serve you for years. Most beginners guess; you reasoned.”
FragileFragile. “Read your lambdas aloud. Is Fn(n) => n + 5 obvious to a stranger? Short lambdas are great, but a lambda doing something tricky deserves to become a named function (Lesson 5) so the reader isn’t forced to decode it inline. Clever is not the same as clear.”
Step 7

Reflection Retro

The apprentice does the talking.

  1. In your own words: what does it mean to ‘hand a function to another function’? Why is that more powerful than writing the loop yourself?
  2. Fold did the same job as your Lesson-6 recursion. Which did you understand more deeply — the hand-built recursion, or the packaged Fold? Does using Fold feel different now that you’ve built its guts by hand?
  3. You’ve now met two ways to work through a list: Each (Lesson 4) and Map/Filter/Fold (here). What’s the key difference? (Hint: which ones give you a new value back, and which just does an action?)
Step 8

Critical-Thinking Takeaway

One durable principle.

PrincipleSeparate what to do from what to do it to. Once actions become values you can pass around, you can describe almost any list job — transform, keep, or combine — in a single clear line. This is the peak of Phase 1’s thinking, and it’s exactly the mindset you’ll carry into the later phases: you’ll describe the operation you want, hand it off, and check that the result is right.
What’s nextEnd of Phase 1. Every line was yours. You’ve never once asked the Craftsman to write code — and that’s the point. You now know what correct Shoddy is supposed to look like and do. In Phase 2 you’ll start judging code you didn’t write; by Phase 4 you’ll prompt the Craftsman to write it — and be able to tell whether it’s any good.
