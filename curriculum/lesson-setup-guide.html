Lesson Setup Guide

How to stand up a VS Code working folder for an apprenticeship lesson and get the Craftsman talking — on Windows or macOS.

These steps repeat for every lesson folder. They assume the one-time machine setup is already done — mill built, SHODDYLIB set, and shoddy.millPath in User settings. If any of those words are unfamiliar, do that page first; it runs once per machine.

Platform note. Paths below are shown per platform; Linux and WSL follow the macOS forms. Where a keyboard shortcut says Ctrl+…, macOS uses Cmd+….

FIRST

Before your first lesson

Do the one-time machine setup once per machine: build the mill, set SHODDYLIB where the VS Code process sees it, set shoddy.millPath in User settings, and smoke-test the whole chain from a folder outside the repo. That page also explains why those choices matter (how Include finds machines/, and which of the extension’s five mill invocations inherit which environment). Nothing below works reliably until that’s done.

STEPS

Per-lesson working folder

Repeat for every lesson.

  1. Create a folder for the lesson, e.g. C:\apprentice\lesson-01\ (Windows) or ~/apprentice/lesson-01/ (macOS). One folder per lesson keeps each apprentice attempt isolated and avoids stale files from a prior lesson confusing a fresh Craftsman session.
  2. Open it in VS Code: code C:\apprentice\lesson-01 (or code ~/apprentice/lesson-01). No .vscode/settings.json is needed here — the User-scoped shoddy.millPath from the one-time setup already covers it. (Only add a workspace .vscode/settings.json if this particular folder needs to override the mill path or add terminal.integrated.env entries for some other reason.)
  3. Leave the file empty for now — the lesson’s own Step 2 (the Challenge) tells the apprentice what filename to create and what to write; don’t pre-create it or the Craftsman’s ritual is short-circuited.
  4. Start a chat with your model provider and paste that lesson’s instructions prompt into the system-instruction slot — for Lesson 1, the Craftsman prompt page has the prompt with one-click copy; the agent context reference page has the per-provider table of which slot to use and the minimum model versions.
    NoteAs of this repo’s current state, only Lesson 1 (the Craftsman prompt page) has a written instructions prompt. Lessons 2–7 exist as built student pages (lesson-0N.html) but have no authored Craftsman prompt yet — that’s the open item tracked separately; don’t paste a student lesson page in as if it were the prompt.
  5. Attach the agent context reference as background reference in the same chat if your provider supports file upload (the linked page has the whole reference with one-click copy). For Lesson 1 this is optional — its <shoddy_facts> block is already self-contained. From the Include-using lessons onward (and for anything touching records, sum types, or the machines/ library — currently unscheduled but real, see the reference’s §17) it’s the reference that keeps the Craftsman accurate without widening what it’s allowed to teach — the lesson’s own <shoddy_facts> still governs scope, per its §0.
  6. Let the Craftsman open — its <opening> block fires the first turn automatically; no prompt needed from you beyond sending the system instructions.
  7. Work the lesson in the open folder: apprentice writes, runs (▶ / Ctrl+Shift+B / Cmd+Shift+B), predicts, and — once the perch is relevant — debugs (F5), exactly as the agent context reference §1 and doc/vscode.html describe.
SPLIT

Apprentice-authored Include files

Once a lesson moves past a single file, the apprentice doesn’t need SHODDYLIB or any setup at all to split their own program in two — Include checks the including file’s own folder first, before ever consulting SHODDYLIB. So a sibling file just works:

lesson-05/
    main.shoddy       ' Include "helpers.shoddy"
    helpers.shoddy

and a personal subfolder works the same way this repo’s own tst/ reaches machines/ (Include "../machines/matrix.shoddy"):

lesson-15/
    project.shoddy     ' Include "lib/vectors.shoddy"
    lib/
        vectors.shoddy

Two things to tell an apprentice once they reach this point (see the agent context reference §3 for the underlying rule): don’t name a personal file the same as a real machines/*.shoddy file (str.shoddy, seq.shoddy, stats.shoddy, …) — the local one silently wins with no warning, so Split or Sum would quietly stop being the standard library’s version. And there’s no way to add a second SHODDYLIB-style fallback directory — only relative paths let them reuse a personal file across more than one lesson folder.
