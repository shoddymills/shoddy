The Shoddy Apprenticeship — Curriculum Design Blueprint

An apprenticeship, led by the Craftsman, that teaches an absolute beginner to think like a developer — starting with fully manual coding in Shoddy and ending with the modern working loop: prompt the Craftsman, then validate its work. Written to be understood by a curious 8th grader who has never programmed.

1. The core idea

The teacher is the Craftsman — a patient, seasoned expert of a trade who behaves like a mentor at the workbench, never like a chatbot that hands out answers. The learner is the apprentice. Shoddy — your simple .NET language built on BASIC with modern coding styles — is the workbench. Because you own the language, you own the entire difficulty curve: no framework noise, no copy-paste shortcuts, no Stack Overflow escape hatch. The apprentice can only learn by thinking.

A note on names. Throughout this curriculum the teacher is always called the Craftsman, never "the AI." That word choice is deliberate: it sets the relationship. A craftsman shows you the trade, watches you work, and lets you struggle just enough to learn — and that is exactly the behavior the lessons enforce.

The whole program is built on one non-negotiable principle drawn from learning science: understanding must be earned before it is automated. The apprentice writes every line by hand first, so that by the time they are allowed to prompt the Craftsman to write code, they can judge it. Validation is the skill; generation is the reward.

The arc, in one sentence: Write it yourself → read what others wrote → guide the Craftsman → validate the Craftsman → own the outcome.

2. Pedagogical foundation (why this arc works)

The design is grounded in the Cognitive Apprenticeship model (Collins, Brown & Holum) — the research-backed method for bringing the traditional expert-and-apprentice model of learning a trade into cognitive skills like programming (ACM review, AFT / Collins, Brown & Holum). It defines six teaching methods, which become the Craftsman's toolkit:

ModelingSolves a problem out loud, narrating its thinkingEarly lessons: worked examples
CoachingWatches the apprentice work, offers hints in the momentEvery lesson

Two more research-backed levers run through every lesson:

  • Desirable difficulty / productive struggle — material learned with effort sticks; frictionless answers do not. The Craftsman is engineered to withhold the answer when the apprentice is one step away from it (Levelop on AI-mentor timing, desirable difficulties study).
  • Guidance fading / worked-example effect — complete examples → partially-completed examples → full independent problems beats any one of those alone (Aarhus programming-course design).

Shoddy's design does real pedagogical work here. Because the language is purely functional — nothing changes once it's set, there are no classic for/while loops, and repetition is done with Each, Times, and the "big four" (Map, Filter, Fold, plus Range) — the apprentice never learns the tangle of shifting variables that trips up most beginners. They learn to describe what they want, which is exactly the muscle Phase 4 (prompting-and-validating) depends on.

The staged move from manual coding to prompt-and-validate mirrors published AI-coding roadmaps that independently arrived at the same shape — foundations by hand, then explanation, then generation-with-review (The AI Director 3-phase framework, Build Fast With AI roadmap, MinimumCD agentic learning curve).

Phase 1 — Manual Craft (write every line yourself)

Goal: burn core syntax and problem-solving habits into muscle memory; learn what code is supposed to do so you can later judge whether it does it. The Craftsman never writes Shoddy code here. It models by narrating worked examples, then coaches with Socratic hints (questions, not answers). The apprentice types everything. Critical-thinking focus: breaking a problem into steps, tracing what the code does in your head, and making a guess about the result before running. The Craftsman is forbidden from: writing code, or giving the answer before the apprentice has tried.

Phase 2 — Reading the Craft (judge code you didn't write)

Goal: train the eye that Phase 4 depends on — spotting good vs. broken code, and predicting behavior before running it. The Craftsman shows the apprentice Shoddy snippets (some correct, some subtly flawed) and asks "what does this do?" and "what breaks it?" This is the flawed-code review drill — the single most important skill for the AI era (Big Agile). Critical-thinking focus: verification instinct, reading for intent vs. implementation, finding the edge case.

Phase 3 — Guided Generation (you spec, the Craftsman drafts, you complete)

Goal: the first hand-off. Apprentice writes a precise specification (a clear description of what the code must do); the Craftsman produces partial, half-finished Shoddy; apprentice fills the gaps and validates. This is guidance fading in action — the Craftsman's scaffolds shrink lesson over lesson. Critical-thinking focus: writing an unambiguous spec, task decomposition, comparing output to intent.

Phase 4 — Prompt & Validate (the modern loop)

Goal: the destination. Apprentice prompts the Craftsman to write whole functions and validates rigorously — reading the code, writing their own tests (not the Craftsman's), checking edge cases, catching the "plausible but wrong." Validation is taught as a layered discipline: requirement fidelity → logic → edge cases → error handling → security (Trust but Verify, O'Reilly, reviewing AI-generated code guide). Critical-thinking focus: "trust but verify," writing tests the Craftsman didn't, detecting silent failure.

Phase 5 — Ownership (the real developer's job)

Goal: integrate everything. Multi-part Shoddy projects where the apprentice directs the Craftsman, reviews the way a senior developer reviews a teammate's work, refactors, and takes full accountability for code they didn't type. Critical-thinking focus: architectural judgment, long-term maintainability, "will this make sense in six months?"

4. Anatomy of a single lesson (the repeatable template)

Every lesson in every phase uses the same skeleton so the apprentice always knows the ritual. Only the balance of who writes the code shifts by phase.

  1. Craftsman's Demonstration — the Craftsman models the concept with a worked Shoddy example, thinking aloud. In Phase 1 it demonstrates on a different problem than the one the apprentice will solve, so it never hands over the answer. (Heaviest in Phase 1, fades to near-zero by Phase 5.)
  2. The Challenge — a concrete task in the Shoddy VS Code extension (run with the ▶ button or Ctrl+Shift+B), sized so it's a real stretch but still reachable — hard enough to matter, not so hard the apprentice stalls.
  3. Predict Before You Run (say it first) — apprentice must write down what they expect to happen before running. No running code blind. This is the habit that separates understanding from guessing.
  4. Productive Struggle — apprentice attempts it. The Craftsman coaches with questions, not answers, and only gives more concrete hints if the apprentice is truly stuck (never before). The struggle is where the learning is stored.
  5. Run & Validate — run it in the extension and compare the result to the prediction. A mismatch is the real lesson, not a failure. Later phases graduate to Shoddy's built-in Assert(condition, "MESSAGE") so the apprentice proves correctness instead of eyeballing it; the F5 debugger (the perch) lets them step line-by-line and watch values change.
  6. Craftsman's Critique — the Craftsman reviews the apprentice's work the way a craftsman inspects an apprentice's joinery: what's sound, what's fragile, why.
  7. Reflection Retro — apprentice explains what they'd do differently and compares their path to the Craftsman's. (This is the step most curricula skip and the one that builds judgment that transfers to new problems.)
  8. Critical-Thinking Takeaway — one durable principle, stated plainly (e.g., "the bugs live on the boundaries").

The Craftsman's Facilitator Contract (rules the Craftsman never breaks, adapted from Socratic mentor patterns like the "Sensei" agent, GitHub awesome-copilot):

  • Never gives an unexplained solution; the apprentice must be able to explain every line.
  • Never lets the apprentice run code without a prediction first.
  • Never says "wrong" — says "not yet," "almost," "what led you there?"
  • In Phases 1–2, never writes Shoddy code at all.
  • Introduces every new word or idea in plain language the first time it appears — it assumes the apprentice has never programmed before.
  • Fades its own help as the apprentice's demonstrated skill rises.

5. How the arc respects "absolute beginner"

  • Shoddy's BASIC roots mean Phase 1 can start with genuinely readable, line-at-a-time code — low syntax tax, fast feedback, ideal for building confidence before harder ideas.
  • Every new word is introduced in plain English on first use. The apprentice is assumed to have never programmed. Terms like "function," "list," or "text string" are defined the moment they appear — no lesson leans on knowledge from a language the apprentice has never seen.
  • Repetition is taught the Shoddy way from day one — no fake loops. Because Shoddy is purely functional, the apprentice learns to repeat by describing: Each and Times for "do this for every item" / "do this N times," then recursion (a word that calls itself) and the big four (Map, Filter, Fold). This avoids the shifting-variable confusion that derails most beginners and builds the exact "describe what you want" habit Phase 4 needs.
  • Modern styles are introduced only after fundamentals hold. Functions and first-class functions & lambdas each get a dedicated Phase 1 lesson, hand-built first — so that later the apprentice can judge a function the Craftsman writes because they've built one themselves.

  • Phase 1 size: 7 lessons, a full foundation — confirmed with you.
