Shoddy Documentation

Making useless things useful, through skill.

This is the cloth hall — where every finished piece is laid out, and where each kind of visitor finds their door. Shoddy is a purely functional BASIC: friendly typed syntax on the surface, a concatenative stack core underneath, compiled onto .NET by the mill, with a standard library of machines.

Pick your door

Never programmed before?
Start with the Apprenticeship — seven hands-on lessons that assume nothing, taught alongside an AI craftsman. The Approach explains the thinking behind it, and the Roadmap shows the whole five-phase arc.
Know your way around a language?
The Beginner’s Guide is the door in — ten short chapters from Print("HELLO") to a working grade book, with BASIC-veteran notes at the end. Set up your editor with Shoddy in VS Code.
Mid-program and need a word?
The Quick Reference — every builtin word, type, and syntax form on one page, plus a map of the library. Each machine’s full word reference lives in the machines catalog: statistics, matrices, money, ISAM files, linear programming, graphics, turtles, charts, sound, and more.
Want the law, or the machinery underneath?
The Language Specification — including Appendix A, the concatenative core every surface form desugars to, and Appendix B, the design rationale. The day-by-day story of the build is in the devlog.
Wondering about the name?
The Heritage of the Name — the shoddy mills of the West Riding of Yorkshire, which made new cloth from old rags for a century and a half, and why this language is built the same way. Five minutes, worth it.

Build and run

The mill is not committed — build it once (requires the .NET 10 SDK), then run programs with it:

dotnet publish src/Shoddy.Mill -c Release -o bin   # build the mill
bin/mill run tst/examples.shoddy                   # compile in memory and run
bin/mill run tst/libtest.shoddy                    # assertion suite
bin/mill weave tst/simplex.shoddy                  # compile to a .dll

Or use the wrapper: ./build.sh build / build.cmd build, then ./build.sh test. The whole story is in the README.
