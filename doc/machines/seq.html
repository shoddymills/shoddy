seq Sequences — machines/seq.shoddy

Summary

seq is the workhorse toolbox for working with lists of things: add them all up, find the biggest, keep only the ones that pass a test, sort them, stitch two lists together, and so on. It's the pile of everyday verbs you reach for the moment you have more than one of something. None of it is built into the language — every word here is written in plain Shoddy on top of a handful of built-in building blocks (Fold, Map, Filter, and the trio First/Rest/Prepend that take a list apart and put it back together). Pure and self-hosted: nothing here touches a file or the screen, so the same input always gives the same answer, and you can read the whole machine like a recipe book.

Why It's Useful

Almost every program ends up juggling a bunch of values at once — a list of scores, a row of prices, the words in a sentence, the students in a class. The language gives you the raw ability to loop over them, but writing the same little loop by hand every time (to total a column, to count how many are over the line, to grab the first three) gets old fast, and every hand-written loop is a fresh chance to get an off-by-one wrong. seq hands you those loops already written, named, and tested, so you can say what you mean — Sum(scores), Sort(prices), CountIf(students, passed) — instead of spelling out how. It's also the quiet foundation a great many other machines are built on: when another machine needs to fold, filter, or sort a list, it leans on seq rather than reinventing it.

One thing worth knowing up front: Shoddy has two flavours of sequence, the List (grown from front to back with First/Rest/Prepend) and the Array (a fixed block you index into). Some words here are poly — they work happily on either kind, because they only ever ask a sequence to fold or map over itself. The aggregations (Sum, Product, Maximum, Minimum, Average) and the predicates (Any, All, CountIf, Contains) are all poly. The rest — searching, slicing, sorting, and pairing — are List-only, because they take the sequence apart with structural recursion, and that's a List's trick, not an Array's. The Word Reference below labels which is which.

User's Guide

Include the file and the words are yours. Most of them take a list as their first argument; the ones that test each element (like Any, All, CountIf) take a little function too — often written inline as a Fn lambda, or as a partially-applied operator like >(4) (read "greater than 4").

Include "seq.shoddy"

Def Main()
    Let xs = { 5, 3, 8, 1, 9, 2 }

    Print(Sum(xs))                       ' 28
    Print(Maximum(xs))                   ' 9
    Print(Average(xs))                   ' 4.6666...

    Print(CountIf(xs, >(4)))             ' 3   (5, 8, 9)
    Print(Any(xs, =(8)))                 ' True
    Print(Contains(xs, 7))               ' False

    Let top3 = Taken(Sort(xs), 3)
    Each(top3, Fn(n) => Print(Str(n)))   ' 1, then 2, then 3

    Print(IndexOf(xs, 8))                ' 3   (8 is the 3rd item)

    Let names = { "ADA", "LIN", "GRACE" }
    Each(Zip(names, xs), Fn(pr) => Print(Fst(pr) & " = " & Str(Snd(pr))))
                                         ' ADA = 5, LIN = 3, GRACE = 8

A few things worth remembering:

  • Nothing is changed in place. Shoddy values are immutable, so words like Sort, Append, and Taken hand you back a brand-new list and leave the original untouched. Chain them freely — Taken(Sort(xs), 3) sorts a copy, then takes three from that.
  • Indexes are 1-based. IndexOf returns 1 for the first item, and 0 when the value isn't in the list at all — a handy "not found" signal. IndexFrom does the same but lets you start the search partway along.
  • Empties behave gently — mostly. Taking or dropping more items than a list holds just stops at the end rather than complaining. But a few words assume there's something there: Maximum, Minimum, and Last reach for a first or final element, so an empty list has no sensible answer to give them.
  • Zipping stops at the shorter list. Zip and ZipWith pair items up position by position and stop when either list runs out — three names against six numbers gives three pairs, as in the example.
  • Poly where it can be. If you're holding an Array rather than a List, the aggregations and predicates still work on it directly; for the List-only words, convert to a List first.

Because it's the common vocabulary of lists, seq shows up underneath a lot of other machines — anywhere a machine needs to total, filter, or sort, it tends to Include this one rather than roll its own.

Word Reference

19 words, plus the Pair type

Aggregation poly — List or Array

WordDescription
Sum(xs)Adds every number in xs together. The total of an empty list is 0.
Product(xs)Multiplies every number in xs together. The product of an empty list is 1.
Maximum(xs)The largest number in xs. Needs at least one item — an empty list has no maximum.
Minimum(xs)The smallest number in xs. Needs at least one item — an empty list has no minimum.
Average(xs)The mean: the sum divided by how many there are. An empty list would divide by zero.

Predicates poly — List or Array

WordDescription
Any(xs, p)True if the test p holds for at least one item in xs. False for an empty list.
All(xs, p)True if the test p holds for every item in xs. True for an empty list (nothing fails it).
CountIf(xs, p)How many items in xs pass the test p.
Contains(xs, v)True if the value v appears somewhere in xs.

Searching List only

WordDescription
IndexOf(xs, v)The 1-based position of the first v in xs, or 0 if it isn't there.
IndexFrom(xs, v, k)Like IndexOf, but treats the front of xs as position k — the building block IndexOf is written on, useful directly when you want to number from something other than 1.

Slicing and building List only

WordDescription
Taken(xs, n)A new list of the first n items of xs. If xs is shorter, you get all of it; if n is zero or less, you get an empty list.
DropN(xs, n)A new list with the first n items of xs removed. Drop more than there are and you get an empty list.
Append(xs, x)A new list that is xs with x tacked on the end.
Last(xs)The final item of xs. Needs a non-empty list.
Flatten(xss)Takes a list of lists and joins them end to end into one flat list.

Sorting List only

WordDescription
Sort(xs)A new list with the numbers of xs in ascending order. A tidy self-hosted quicksort, built by partitioning around a pivot with Filter.

Pairing List only

WordDescription
PairA two-value bundle with fields Fst and Snd — what Zip hands back for each matched-up couple.
Zip(xs, ys)Pairs up xs and ys position by position into a list of Pairs, stopping when the shorter list runs out.
ZipWith(xs, ys, f)Like Zip, but instead of making pairs it calls f on each matched couple and collects the results. Zip is just ZipWith with Pair as the combiner.
