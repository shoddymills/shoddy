seedbool

A reckoner seed: bool's binary layer — machines/seeds/seedbool.shoddy

← seedrandomAll machinesAll machines →

Summary

seedbool bridges bool's binary layer into the reckoner engine: HEX BIN INBASE FROMBASE, BITAND BITOR BITXOR BITNOT SHL SHR, MASK GETFIELD BITAT POPCOUNT, and the six logic gates the engine core does not already own — NAND NOR XOR XNOR IMPLIES IFF. Its whole public surface is one function: fold RckSeedBool over a state and all twenty words are in the dictionary.

It is the widest seed, because bool is the widest domain bridged. Bases, bit operations, masks and gates are four families that share nothing but the value they work on, and a keyboard that has one of them and not the others is a keyboard that cannot finish the job.

Why It's Useful

Every Bool* word aborts on a bad domain, and nothing keyable may. That is the whole work of this file. bool is deliberately the strictest machine in the tree — it refuses a negative, a fraction, a value that does not fit its width, a width outside 1..53, a base outside 2..36 — and every one of those refusals is an Error, which would take the mill down with it. So each word here asks the question bool would abort on first, and answers a refusal instead. R4.1, applied to a machine that guards itself thoroughly and in the one way a reckoner cannot use.

The guard helpers answer a reason string, empty when there is nothing wrong, rather than a Result — the question is only ever "may this proceed, and if not why not", and there is no payload to carry.

Every guard tests its reason with If/Then/Else and never Ifte. Ifte is an ordinary call, so both of its arms are evaluated before it chooses between them — handing it a Bool* word as one arm would run exactly the abort the guard was written to prevent. If/Then/Else compiles to two quotations and one Ifte over them, so only the chosen arm runs. It is the single most dangerous thing in the file to "tidy up".

User's Guide

Let st0 = RckSeedBool(RckNew())
RckEval(st0, "255 HEX")                  ' x: "FF"
RckEval(st0, "12 10 BITAND")             ' x: 8
RckEval(st0, "171 7 4 GETFIELD")         ' x: 10
RckEval(st0, "1 7 8 SHL")                ' x: 128

A register decoded at the keyboard, which is what the field words are for — 180 is 1011 0100, and there are no hex literals in Shoddy, so a value is typed in decimal or read with FROMBASE:

RckEval(st0, "180 5 2 GETFIELD")         ' x: 13   — bits 5..2
RckEval(st0, "180 7 BITAT")              ' x: True — the top bit
RckEval(st0, "180 BIN")                  ' x: "10110100"

Refusals name the bound they are enforcing, not merely that something was out of range, because "1 to 53" is the fact a caller needs and "bad width" is not:

RckEval(st0, "256 8 BITNOT")   ' BITNOT needs a value that fits 8 bits, and 256 does not
RckEval(st0, "0 54 BITNOT")    ' BITNOT needs a width from 1 to 53, got 54
RckEval(st0, "5 37 INBASE")    ' INBASE needs a base from 2 to 36, got 37
RckEval(st0, "TRUE 1 XOR")     ' XOR needs a BOOLEAN, got NUMBER

FROMBASE is the one guard this seed translates rather than invents. Reading text is not a bug, so bool answers a Result there; this turns it into a refusal carrying the 1-based position. The message names FROMBASE and not BOOLFROMBASE — the prefix up to the first colon is replaced rather than repeated, since naming two words for one refusal names neither of them clearly:

RckEval(st0, "\"1F\" 2 FROMBASE")  ' FROMBASE: '1F' HAS NO DIGIT F IN BASE 2 at position 2

Word Reference

Bases and rendering

WordDescription
HEX ( n -- s )n written in hexadecimal, uppercase.
BIN ( n -- s )n written in binary.
INBASE ( n base -- s )n written in the given base, 2 to 36, uppercase letters past 9; refuses a base outside that range.
FROMBASE ( s base -- n )The digit string s read in the given base, case-insensitively; refuses a digit the base does not have, naming its 1-based position, and refuses the empty string.

Bit operations

WordDescription
BITAND ( a b -- c )Bitwise AND. Needs no width.
BITOR ( a b -- c )Bitwise OR. Needs no width.
BITXOR ( a b -- c )Bitwise XOR. Needs no width. These three are the only width-free words, here as in bool itself.
BITNOT ( a width -- c )Bitwise NOT within the given width; refuses a width outside 1..53 and a value that does not fit it.
SHL ( a n width -- c )a shifted left n places within the width, bits above it falling off; refuses a shift past 53.
SHR ( a n -- c )a shifted right n places, zeros coming in at the top. Needs no width, because a logical right shift cannot produce a bit the input did not have.

Masks, fields and inspection

WordDescription
MASK ( n -- m )A mask with the low n bits set, n from 0 to 53.
GETFIELD ( a hi lo -- v )Bits hi down to lo of a, inclusive and 0-based, shifted down to zero; refuses an inverted field and an index past 52.
BITAT ( a k -- flag )Whether bit k of a is set. Answers a BOOLEAN, never 1 or 0.
POPCOUNT ( a -- n )How many of a's bits are set.

The six gates the core does not own

All on BOOLEAN, all one line each over RckBool2, which names the kind it got instead when handed something else. They have to be here: a user word takes exactly one cell, so a keyboard user cannot define a two-argument XOR for themselves.

WordDescription
NAND ( p q -- r )NOT (p AND q).
NOR ( p q -- r )NOT (p OR q).
XOR ( p q -- r )True when exactly one of p and q is true.
XNOR ( p q -- r )True when p and q agree.
IMPLIES ( p q -- r )False on exactly one row: p true and q false.
IFF ( p q -- r )Material equivalence — the same answer as XNOR, under a logician's name.

Not bridged

Left outWhy
AND, OR, NOTThe engine core owns all three as Boolean words already. Bridging bool's would give two spellings for one idea, which is the rule seedmath applied to Rad and Deg.
Truth tables and minimisationBoolTruthTable answers a List Of BoolRow and BoolMinimise a List Of BoolTerm, and neither is a cuttle Cell — the value set has no case for either. Bridging them means inventing a stack representation for a product term, which is a design and not a bridge.
BoolLowBit, BoolHighBitThey answer an Option, and None() at zero is an ordinary answer a stack has nowhere to put. A word that refused on zero would contradict the contract bool itself draws. POPCOUNT and BITAT answer the questions a keyboard actually asks.
BoolCardIts glyphs are UTF-8 and file I/O is Latin-1, so a card that reaches a tape or a saved session is a row of question marks. BIN is the render that survives being written down.
The rotates, BoolShrA, two's complement, the codesBridgeable, and deliberately left: each wants a width the keyboard must keep supplying, and a seed of forty words has stopped being a bridge and become a second dictionary. A mill that wants them registers them itself — RckReg is public, and that is the whole point of the seed pattern.

Who Uses It

UserHow
halifaxThe calculator's bases and bitwise/boolean words: HEX, BIN, BITAND, BITOR, SHL, SHR, NAND, XOR and the rest of the table.

A mill claims this seed by folding RckSeedBool over its reckoner state, which is all halifax does. tst/seedtest.shoddy exercises every word and every refusal above.

The Machines It Uses

MachineWhy
