weather-glass

A 72-hour forecast in VT100 — mills/weather-glass

Summary

Give it a US ZIP code and it draws the next 72 hours off the National Weather Service — temperature, what it feels like, conditions, precipitation, humidity and wind — banded light and dark for day and night, with a bold marker at each sunrise and sunset.

cd mills/weather-glass
./build.sh run 63011     # the network is needed for this one
./build.sh test          # and never for this one
63011 Ballwin, Missouri

Mo 3  15    85 (88)  Mstly Sunny     0%  25%  55%   NE   1

A weather-glass is what a barometer used to be called: the instrument in the hall you tapped to read the coming weather.

Four hops

#HostWhat it gives
1api.zippopotam.usThe ZIP becomes a place name and coordinates.
2api.weather.gov/pointsThe coordinates become two forecast URLs.
3the daily forecastThe highs, lows and wind for the marker rows.
4the hourly forecastThe rows themselves.

Every hop is status-gated. Shoddy has no catchable errors, so a clean abort naming the hop is the error handling — an unknown ZIP stops at hop one saying so, and a non-200 anywhere names the host, the path and the status.

Both hosts get a User-Agent: the weather service answers 403 without one, and zippopotam gets one out of courtesy. Coordinates are trimmed to four decimals before hop two, because the API has historically redirected long ones and this client follows no redirects.

The seam

The shell does four fetches and a Print. Everything else — parsing, the calendar, the sun, the feels-like formulas, the abbreviation table, the banding and all 58 columns of layout — is pure, in weather-glass-core.shoddy and weather-glass-sun.shoddy:

Def Render(p As Place, hours As List Of Hour, days As List Of DayInfo) As List Of String

Records in, every line of the report out. So test.shoddy feeds it the captured API responses in files/ and compares the result against files/expected.out line by line, with no network and no --allow-net. Escape sequences are bytes like any others; the golden file simply contains them.

It is the same split mungo-caverns draws by making a turn a function and rag-and-bone draws by making a request one. Put the I/O at the edge and the middle becomes gradeable.

Under the Hood

The sun is computed, not fetched

There is no fifth hop for sunrise and sunset. weather-glass-sun.shoddy carries the NOAA solar-position algorithm — fractional year, equation of time, solar declination, hour angle at a zenith of 90.833° — in about forty lines of arithmetic over math's Rad and Deg and the trig builtins. It is graded against published values to within two minutes, and the reference rendering this mill mirrors is itself one of those values: it puts sunset on 2 May 2026 at 7:56 PM, and the algorithm computes 7:54.

Above the Arctic circle in June the sun does neither, and the cosine falls outside the domain Acos accepts — so that is checked before it is called, and such a day reports -1 rather than aborting.

The weekday comes from Sakamoto's congruence: five lines and a twelve-entry table, no date type anywhere in the language or in the mill.

The cloud column is an estimate

Say it plainly. The hourly feed carries no sky cover — that lives only in the raw gridpoint endpoint, a fifth fetch of some 212 KB in UTC intervals — so the Cld column is inferred from the words in the forecast: "Mostly Sunny" becomes 25%, "Cloudy" 95%, anything raining 75%. A condition the table does not recognise renders as a blank cell rather than a guess. Every other number in the table came from the API.

What it feels like

The hourly feed gives temperature, humidity and wind, which are exactly the inputs of the two standard NOAA formulas: wind chill below 50 °F with a wind over 3 mph, and the Rothfusz heat-index regression above 80 °F with its two humidity adjustments. Both are transcribed rather than improvised, and both are checked against the published tables — 35 °F at 10 mph reads 27, and 90 °F at 70% humidity reads within a degree of the chart's 105. Between the two ranges, what it is is what it feels like.

The layout is 58 columns with uneven gaps

The reference rendering puts one space between some fields and two between others. That is reproduced exactly rather than tidied into a uniform grid, because a report that is nearly the reference is a report somebody has to check by eye forever. A test asserts the header is byte-identical and that every row is the same width.

The fixture has one deliberate lie in it

The captured responses are the live ones, with a single edit: one hour's probabilityOfPrecipitation is set to null. That day's capture happened to contain none, but the API does return null there, and a mill that aborts at three in the morning because precipitation was null has not used the total accessors json provides. The edit is the test.

The Machines It Uses

MachineWhy
httpsAll four hops, over TLS, with the status and headers read back by its pure half.
jsonEvery response. Object keys with spaces in them, coordinates that arrive as strings, and a null that has to read as zero.
vt100The banding: day rows plain, night rows dim, markers bold, header reversed.
mathRad and Deg for the solar algorithm.
netUnderneath https; the mill never touches a socket itself.
strPadLeft, PadRight, PadZero and ToFixed lay out the columns.
seqTaken cuts the feed to 72 hours; the render accumulates with Prepend.
fileThe offline test reads the fixtures and the golden render.
