Shoddy Documentation

The Language Specification

The whole language, defined — with the stack core and the design rationale as appendices

The name is from the shoddy trade of the West Riding of Yorkshire: from 1813 the mills of Ossett, Morley, and Wakefield tore worn-out rags back to fiber (in a machine called the devil), blended the reclaimed stock with new wool, and wove it into cloth again — until synthetic fibers ended the trade. The language is built the same way: old ideas reclaimed, blended with new wool, woven into something useful. The executable is the mill; the libraries are its machines. The full story is in the heritage of the name.

Shoddy is a purely functional BASIC. Its surface syntax is typed and applicative — parenthesized calls, infix operators, Let, Fn — and it desugars onto a concatenative (stack-based) core in the tradition of Joy and Kitten. Both styles are legal and mix freely:

Def Hypot(a As Number, b As Number) As Number
    Sqr(Square(a) + Square(b))

Def Square ( Number -- Number )
    Dup *

Pedigree: Kitten’s semantics, BASIC’s keywords, Python’s layout.

1. Philosophy

  • Purely functional: no variables, no assignment, no goto, no mutation. Let binds; it never rebinds.
  • Iteration is recursion or a combinator (Map, Fold, Filter, Each, Times). There is no mutable loop index — for is a mutable index in a trenchcoat, so it doesn’t exist.
  • Every definition compiles to a pure stack-to-stack function. The stack is the compilation target; most programs never mention it.
  • Layout is structure: indentation delimits bodies and branches. No endif, no end def, no ;, no line numbers.
  • Effects live at the edge: by convention Print appears only in Main.

2. Lexical structure

  • Case-insensitive — the mill folds case entirely, so Map, MAP, and map are the same word. Convention: PascalCase for keywords, types, functions, and field accessors (Def, Number, MatMul, Score); camelCase for variables and parameters (xs, bestRatio). Records print back in their declared spelling.
  • Self-delimiting characters: ( ) { } [ ] , — everything else splits on whitespace.
  • Numbers: 42, -3, 1.5 (IEEE double).
  • Strings: double-quoted, single line. Escapes: \" \\ \n \t \r.
  • Comments: Rem or ' to end of line.
  • Line continuation: a line whose brackets are still open continues onto the next physical line — wrap long calls after a (, {, [, or any comma inside them. Continuation lines carry no indentation meaning; comments and blank lines may appear mid-continuation. Any long expression can be made wrappable by parenthesizing it. A Def at the left margin always starts a new function, so a missing close bracket is reported at the line that opened it.
  • Reserved characters: BASIC’s type sigils ! % # $ and the predicate suffix ? may not appear in words. Types live in declarations, not names. Predicates use the Is prefix (IsEmpty, IsEven) after Visual BASIC’s IsEmpty/IsNumeric; string words are de-sigiled (Str, Mid, Left), matching Val and Asc which never had a sigil.

Implementation status: annotations are parsed; type checking happens at runtime (wrong types abort with a line number). The mill's weave-time linter performs stack-effect inference — net effects per Def, branch agreement, call-site depth against declared arities, and unknown words as weave errors — warning only on what it can prove and skipping what it cannot. See The linter. Full static type checking is future work.

4. Definitions

Three header forms, dispatched by shape:

Def Name(p As t, ...) As r      ' applicative body (expression syntax)
Def Name ( t ... -- u ... )     ' concatenative body, effect signature
Def Name                        ' concatenative body, undocumented effect

Applicative parameters perform an implicit Take; the body is a sequence of statements whose final value is the result. Def Main() is the entry point. A fourth top-level form, Let NAME = expr at the left margin, binds a program-wide constant: all top-level Lets are evaluated once, in textual order, before Main, each seeing earlier ones and any Def. They form the outermost lexical scope — visible in every body, closed over by quotations, immutable like every binding. (No separate Const keyword: a Let that can never rebind already is one.)

5. Expressions (applicative bodies)

  • Calls: f(a, b) desugars to a b f — arguments load left to right, then the word runs.

  • Infix operators, low to high precedence: Or; And; comparisons = <> < > <= >=; `+ - &;* / Mod;^(right-associative, so2 ^ 3 ^ 2is 512 and-n ^ 2is-(n^2), as in classic BASIC).Notand unary-` are prefix. Parentheses group.

  • And and Or short-circuit in expression bodies: the right side evaluates only when needed, so Not IsEmpty(xs) And First(xs) > 0 is safe on an empty list. (The core’s postfix And/Or words remain strict — both operands are already on the stack by then.)

  • Let Name = expr binds an immutable local for the rest of the body.

  • Pipeline chaining: adjacency is stack flow. A call may consume the value of the preceding expression, and deeper-indented lines continue a statement:

    Def EvenSquareSum(n As Number) As Number
    Range(1, n)
        Filter(IsEven)
        Map(Square)
        Fold(0, +)

  • Conditionals: If cond Then with indented branches; Else alone on a line at the If’s indent. If is an expression — each branch’s final value is its result. Inline alternative: Ifte(cond, t, f).

  • Select Case — QBasic’s value matching, as an expression. The scrutinee evaluates exactly once; the first matching clause’s block is the result. Clause forms: Case expr (equality), Case e1, e2, ... (any-of), Case a To b (inclusive range), Case [Is] >= expr (any comparison operator), Case Type(n1, ..., nk) [Where cond] (record destructuring: matches records of that Type, binds every field in declaration order to the given names — in scope for the guard and the body), and Case Else (default, last). With no Case Else, a non-match is a runtime error. Desugars to nested Ifte over a hidden one-time binding. Note Case Type(...) is always a pattern; to test equality against a constructed record, write Case = Type(...).

    Def Greet(p As Person) As String
    Select Case p
        Case Person(n, a) Where a < 18
            "HEY " & n
        Case Person(n, a)
            "HELLO, " & Upper(n)
    Def Grade(score As Number) As String
    Select Case score
        Case >= 90
            "A"
        Case 80 To 89
            "B"
        Case Else
            "F"

6. Function values — where the brackets went

A quotation is deferred code; brackets are the core’s quote marker. In the applicative surface they’re rarely needed:

  1. Bare names auto-quote in argument position. A name that isn’t a local binding is passed as a function value: Fold(xs, 0, +), Map(xs, Square), Filter(xs, IsEven). To force a bare name to evaluate instead, parenthesize it: f((g)).
  2. Sections pre-load an operator’s trailing arguments: Filter(xs, >=(100)) — “≥ with 100 pre-loaded” — instead of [ 100 >= ].
  3. Fn lambdas for anything genuinely inline: Filter(xs, Fn(x) => x Mod 2 = 0). Sugar for a quotation beginning with an implicit Take.
  4. [ ... ] remains legal everywhere as raw core code, and is required inside concatenative bodies, where without the quote marker If’s branches would run before If did.

Call applies a function value: Call(f, acc, x) ≡ acc x f Call.

Quotations are closures. A function value captures the environment where it was created (lexical scoping): Filter(xs, >=(p)) still sees p when a library word executes the quotation later. Since bindings are immutable, capture costs one pointer.

7. Lists

{ 1, 2, 3 } builds a List Of Number; elements are arbitrary expressions, evaluated at construction. Lists are immutable.

Primitives: IsEmpty First Rest Prepend. Library (expressible in the language itself): Map Filter Fold Each Times Range Length Reverse Concat Call Ifte — provided as builtins for speed, self-hostable as:

Def MySum(xs As List Of Number) As Number
    If IsEmpty(xs) Then
        0
    Else
        First(xs) + MySum(Rest(xs))

8. Records: Type

QuickBASIC’s record syntax, minus the end Type that layout makes redundant. Declared at column 0, before first use:

Type Person
    Name As String
    Age  As Number

Declaring a Type generates three things:

  • A constructor word, positional or named (not mixed): Person("ANN", 34) or Person(Name = "ANN", Age = 34). Positional arity is checked at parse time.
  • Accessor words for each field: Name(p), Age(p). Accessors are ordinary words, so they compose with everything: Map(people, Name), Filter(people, Fn(p) => Age(p) >= 18), and in the concatenative core simply p Age. Two TYPEs may share a field name; the accessor dispatches on the record’s tag at runtime. (Don’t name fields after builtins — the builtin wins; the SHODDY_LINT switch on the Toolchain page warns at weave time when a binding shadows an accessor.)
  • Functional update via With, returning a new record: With(p, Age = Age(p) + 1) — any number of field = value pairs.

Records are immutable, compare structurally (=), nest freely (Customer As Person), and print as valid input: Person(Name = "ANN", Age = 34).

Sum types declare tagged alternatives on one line:

Type Shape = Circle(r) | Rect(w, h)
Type Option = Some(v) | None

Each variant is a full record type — constructor, accessors, With, patterns — and Select Case dispatches on the variant:

Def Area(s As Shape) As Number
    Select Case s
        Case Circle(r)
            Pi() * r ^ 2
        Case Rect(w, h)
            w * h

A bare variant (None) has zero fields; construct it as None() (or bare None outside argument position) and match it with Case None (structural equality) or Case None(). Option is the language’s answer to NULL: absence is a value you must match, never a hole.

Patterns nest. A sub-pattern may be a binder name or another Type(...) pattern, to any depth; _ is an ordinary binder used by convention for ignored fields:

Select Case o
    Case Order(Person(n, _), items, total) Where total > 100
        n & " (BIG SPENDER)"

9. Arrays

List is the inductive type — cheap First/Rest/Prepend, made for structural recursion. Array is the indexed type — fixed length, immutable, O(1) Nth, functional SetNth (returns a new array). Use lists to recurse, arrays to index; matrices are arrays of arrays.

Let a = ToArray(Range(1, 5))    ' Array(1, 2, 3, 4, 5)
Nth(a, 3)                       ' 3, in o(1)
SetNth(a, 3, 99)                ' Array(1, 2, 99, 4, 5) — original untouched
Dim(3, 0)                       ' Array(0, 0, 0) — basic's keyword, reclaimed

Map Filter Fold Each Length IsEmpty First Nth SetNth Reverse Concat Sort are polymorphic over both kinds and preserve the input’s kind (Map over an array yields an array). ToArray/ToList convert. Rest/Prepend stay list-only by design — on an array they’d hide an O(n) copy.

12. Tail calls and errors

Tail recursion is the language’s loop (the mill compiles self-tail-recursion to a loop, so the Fact-with-accumulator shape runs in constant stack; mutual recursion still consumes stack). Runtime errors — stack underflow, type mismatch, unknown word, division by zero — abort with a message and source line number.

13. Include and the standard library

Include "FILE.SHODDY" at the left margin splices another source file in at that point — include-once semantics. Resolution: relative to the including file first; if not found there, the directory named by the SHODDYLIB environment variable; then the machine library shipped with the mill that is running — machines/ beside the executable, then one level up, beside its bin/. The fallbacks are what let a program keep a bare Include "seq.shoddy" wherever it is copied: a repo's bin/mill finds machines/ at the root and the mill bundled in the VS Code extension finds the one staged beside it, neither needing anything set, while SHODDYLIB stays the explicit override that pins a checkout to its own machines. A file found in a machine library is a machine, and is always used compiled: the mill links Shoddy.Machines.Seq.dll beside the source, building it first if it is missing or stale. A file found beside the includer — one of your own program's files — is spliced. Declarations must precede use, so libraries go at the top.

13.1 Namespaces

There are two kinds of Include, and the difference is one sentence: a machine is a boundary, and a program's own files are one program. Including one of your own source files splices it — every Def, Type, variant, and field accessor lands in one flat table alongside the builtins, which is what lets a mill split itself across a dozen files without ceremony. Including a machine gives you the words that machine declares, and not the words it includes in turn: Include "stats.shoddy" does not hand you seq's ZipWith merely because stats uses it. Name what you use. The refusal says which Include to add, and the dependency is compiled and linked either way — only the naming is scoped.

Within one file, then, every visible declaration is in one flat table. Include "FILE.SHODDY" As NAME pastes NAME onto the front of everything that file declares: a file included As Msg declaring CaveNearby declares MsgCaveNearby — the same name a hand-written prefix would have produced, so existing call sites keep working.

Qualification is never required at the use site. A bare word resolves while its meaning is unambiguous, in this order: the namespace the use site is itself written in (a file's own names come first, so qualifying two files that share a helper name breaks neither), then an exact declaration, then a unique namespaced name. Only a genuine collision between two namespaces forces you to choose, and the error names both candidates. (This chooses which declaration a name refers to; what a word means when local bindings, Defs, builtins, and accessors all compete is the separate chain described on the Toolchain page.)

To choose, write NAME In NAMESPACE — Hints In Tbl(), Died In Core (m) in a pattern, Anchor In Vocab (k, t) for a constructor. It collapses to the single word TblHints, so both spellings mean exactly one thing.

Three details worth knowing. An As namespaces the surface of the file you named, and nothing further — the words that file declares, not the words it in turn includes. So Include "net.shoddy" As Sock spells net's own Connect as SockConnect and leaves Join, which net gets from str.shoddy, spelled Join. Namespaces therefore do not compose through a chain of includes: a name never depends on who included the includer, and a file's spelling never depends on its dependencies' include lists — adding an include to str cannot change what As Sock spells. Only the accessor word is namespaced, not the field's identity: With(g, Dflag = 3) still names the field bare, and a namespaced accessor is reachable as Key In Vocab (a) even where a local named key would shadow the bare spelling. And a machine include takes As too, which is what lets two machines exporting the same word be used in one program. One pair in the library still does: net.shoddy and turtle.shoddy both export Close. Include both and you name one of them — Include "net.shoddy" As Sock, whose words read naturally prefixed — and leave turtle's bare. Include only one and there is nothing to disambiguate, so you need no As at all: a machine's own dependencies are not part of your program's names, so they cannot collide with anything either.

Two further guards, independent of namespaces: declaring a name twice is an error that names the earlier file and line, and a Def whose name is a builtin is refused, because a Def outranks a builtin everywhere in the program. Write Redef in place of Def when the override is deliberate.

The standard library is written in Shoddy itself:

  • seq.shoddy — the Fold/Map usual suspects, structure only: Any All CountIf Contains IndexOf Taken DropN Append Last Flatten Zip ZipWith, plus Type Pair (Fst/Snd). Aggregation lives in stats.shoddy; sorting is the Sort builtin.
  • matrix.shoddy — Type Matrix over a flat row-major array (O(1) MatGet, dimension-checked ops via Error): Mat MatFill Ident MatFromRows MatGet MatSet MatRow MatCol Dot VAdd VSub VMul VScale Outer MatMul MatAdd MatSub MatScale Transp MatVec MatShow (VMul is elementwise; Outer is the outer product). The algorithms over the type — determinants, inverses, systems, rank, factorisations, eigenvalues — are lin.shoddy; this machine owns the structure and its arithmetic. Includes seq.shoddy.
  • lin.shoddy — linear algebra over matrix.shoddy's Matrix: measures (LinTrace LinNorm LinMaxAbs LinIsSym LinIsSquare), vectors (LinVNorm LinVUnit LinCross), building (LinBuild LinSwapRows LinScaleRow LinScaleCol LinAug LinCols), elimination with partial pivoting (LinRef LinRref LinRank), LinDet LinInv LinSolve LinPow LinMinor LinCofactor LinAdj, the factorisations (LinLuOf → Type LinLu with LFactor UFactor Perm PSign, LinQrOf → Type LinQr, LinChol), and the eigenproblem (LinCharPoly by Faddeev-LeVerrier, coefficients highest power first; LinEigVals; LinEigSym by cyclic Jacobi → Type LinEigen). LinEigVals finds the real eigenvalues only, by bracketing sign changes, so an answer shorter than Rows(m) is itself information; LinEigSym is complete for a symmetric matrix. Every solver checks its precondition and aborts rather than returning a plausible wrong answer. A program normally includes matrix alongside it, since it must name Matrix. Includes matrix, eng and seq.
  • str.shoddy — Split Join Trim Replace StartsWith EndsWith StrRep, built on the Instr/Left/Right/Mid builtins.
  • money.shoddy — exact currency as Type Money over whole cents (exact past $90 trillion in a double; no DECIMAL type needed): Dollars MoneyVal MoneyAdd MoneySub MoneyMul (explicit rounding) MoneySum MoneyLt MoneySplit (penny-preserving allocation) MoneyFmt. Includes str.
  • file.shoddy — line-oriented text files over the whole-file builtins: ReadLines (normalizes \r\n, drops the trailing newline), WriteLines, AppendLine. Includes str.shoddy.
  • fin.shoddy — finance: time value of money (FinPv FinFv FinPmt FinNper and the annuities), loans and amortisation (FinBalance FinAmortAt FinSchedule FinExtraPayoff), appraisal (FinNpv FinNpvOf FinIrr FinMirr FinPayback), small business, the four depreciation methods, a civil calendar (FinDate FinSerial FinDays360) and bonds (FinBondPrice FinYtm FinMdur). Rates are decimal fractions per period; everything is a plain Number in whole currency units, and money.shoddy is deliberately not used — Money has no division, so half of this machine could not be written in it. The statistics a finance report wants are here too, with a Fin prefix, so a caller never has to know which machine a word lives in. Includes seq, stats, math and str.
  • recio.shoddy — record-oriented binary I/O: give it a record size and a reader/writer function and it does the offset arithmetic. RecPos RecSeek RecCount GetRec PutRec AppendRec AllRecs (records numbered from 1).
  • dict.shoddy — dictionaries as association lists (List Of Pair); keys compared with = so any equatable value works. DictPut DictGet DictGetOr DictHas DictDel DictKeys DictVals. Pure; a hashed implementation could replace it behind the same words. Includes seq.
  • stats.shoddy — statistics, pure Shoddy over the Erf/GammaP/BetaI and Sort builtins. Descriptive: Sum Product Maximum Minimum Mean (Average is an alias) WeightedMean GeoMean HarmonicMean Median Quantile Percentile Iqr RangeOf Var VarP StdDev StdDevP StdErr Mad Skewness Kurtosis ZScore ZScores Outliers OutliersZ Freq RelFreq Modes Ecdf Cov Correl Spearman LinFit (→ Fit). Distributions: NormPdf NormCdf Chi2Cdf TCdf FCdf NormInv TInv. Inference (all → TestResult(Stat, Df, PVal), two-sided): TTest1 TTest2 TTestPaired ZTest1 Anova ChiSqGof ChiSqTest TwoPropZTest, plus MeanCI PropCI (→ Pair) and CohenD. Sample forms divide by n−1; quantiles interpolate (R type 7). Includes seq.shoddy and dict.shoddy.
  • isam.shoddy — indexed-sequential files: fixed-length records with a 1-byte tombstone flag per slot, plus a key→slot index kept on disk as a B+tree in a companion file (path & ".idx": header with root page, live count, and free-list head; the free list threads through dead slots' payload bytes). Opening reads the header — O(1), no scan — falling back to a one-time rebuild scan only when the index file is missing; index entries hold slot numbers and keys are re-derived through KeyOf, so Number and String keys both work with no width limit. Mutating words still return the handle (unchanged — it carries only the two file handles and your functions). Keys via a user KeyOf function; deletes free slots for reuse. IsamOpen IsamClose IsamInsert IsamUpdate IsamDelete IsamGet IsamGetOr IsamHas IsamCount IsamAll IsamRange IsamFirst IsamLast IsamNext IsamPrev. Sequential access is cursorless (key-order navigation). No crash safety or concurrency; one live handle at a time.
  • json.shoddy — JSON to RFC 8259, both directions. Type Json = JNull | JBool | JNum | JStr | JArr | JObj, where an object's members are a List Of Pair — dict.shoddy's association list exactly, so JGet/JPut delegate rather than duplicate. Reading is a guard pair: JsonParse aborts, JsonRead is total and returns JOk or JErr(why, at) with the 1-based offset, which is how a program survives input it did not write. The character scanners are self-tail-recursive (so they compile to loops and a long document costs no stack) while value/array/object recursion is mutual and therefore bounded by a depth limit, 200 by default. Numbers are validated against the JSON grammar before Val sees them, since Val is strtod and far laxer. JsonRead JsonReadDepth JsonParse JsonLoad JsonText JsonPretty JsonSave JsonEscape JsonCanonical JGet JGetOr JHas JNth JPath JPathOr JKeys JCount JEqual IsJNull JStrOr JNumOr JBoolOr JPut JDel JNumList JStrList IsFinite. Known limits: Str gives ten significant digits, so arbitrary doubles do not round-trip bit-exactly; a string cannot carry NUL, since Chr(0) is the empty string, so \u0000 is a JErr; duplicate keys collapse with the last value winning; and documents compare with JEqual, not =, because a List compares by identity. Includes seq, dict and str.shoddy and str.shoddy.
  • xml.shoddy — XML 1.0, well-formed, both directions. Type Xml = XDocument | XElem | XText | XComment | XPI | XCData | XDoctype, where an element's attributes are a List Of Pair — dict's association list — so XAttr/XPutAttr are DictGet/DictPut in a hat. Reading returns the whole document, prolog and all, so a round trip keeps the declaration, the comments and the doctype; XRoot reaches the root element. XmlRead is total (XOk/XErr with a 1-based offset), XmlParse aborts. The five predefined entities and numeric references only; the doctype internal subset is deliberately not read, which is also what makes the billion-laughs expansion impossible. Numeric references decode to their UTF-8 bytes, because ReadFile is one byte to one character and a literal character in the file already is those bytes. XmlPretty refuses to re-indent mixed content or anything holding CDATA. Namespaces are carried literally, not resolved. Includes seq, dict and str.
  • html.shoddy — HTML, forgivingly, built on xml and reusing its tree outright: a parsed page IS an Xml, so XFind, XPath, XTextOf and XEqual work on it unchanged. Handles case folding, the fourteen void elements, raw-text script and style, quoted/unquoted/valueless attributes, end tags implied by a sibling or a closing parent, and a stray end tag — which is dropped rather than allowed to close its ancestors, for which the reader threads the open-element stack. About eighty named character references plus numeric ones; an unknown name is left standing as text rather than being an error. Not the HTML5 tree-construction algorithm: no adoption agency, no foster parenting, no invented tbody. Includes seq, str, dict and xml.
  • csv.shoddy — CSV to RFC 4180, both directions. A document is the plain thing it looks like — a List Of List Of String — so seq works on it unchanged; the point of the machine is everything Split(line, ",") cannot do, namely a cell that CONTAINS the separator, a quote or a line break. Quoting is the whole of RFC 4180's escaping: a quoted cell may hold anything and a doubled "" inside one is a single literal quote, and there is no backslash anywhere in it. The reader is total — CsvRead → CsvOk or CsvErr(why, at) with a 1-based offset — and CsvParse is the aborting half. Dialects rather than flags, every reader and writer having an -As twin: CsvComma CsvRfc (CRLF) CsvTabs CsvSemis CsvSepBy, with combinators CsvTrimming (drop spaces around UNQUOTED cells only) and CsvCommented stacking, and CsvNumeric the repo's own .dat spelling. Ragged rows are not an error, because files in the wild are ragged — CsvWidth CsvIsRect CsvRect CsvDropBlanks CsvFlip ask and repair. Compare with CsvEqual, never =: a List is a quotation and compares by identity. Above the rows sit two optional layers. A sheet reads the first record as a header, after which columns have names (CsvSheetLoad CsvHeads CsvBody CsvGet/CsvGetOr CsvNum/CsvNumOr CsvColumn CsvColumnNums CsvWhere), and CsvPairs zips a row with that header into precisely dict's association list — the same arrangement json makes for object members. And a Type: hand CsvRecs/CsvFromRecs the two functions that know your record and the machine never learns it. Writing quotes minimally, plus one rule RFC 4180 does not ask for — a leading or trailing space also forces quotes, so a round trip stays exact under CsvTrimming. A blank line is a record of one empty cell, as the RFC says; the single line ending at the end of a file is the last record's terminator and does not start another. Includes seq, dict and str.shoddy and str.shoddy.
  • shaker.shoddy — reversible obfuscation: a four-round Feistel network over a List Of Number, keyed by another, with a Fletcher-style checksum appended so tampering is detectable. Values are field elements — whole numbers in 0 .. ShakeModulus() - 1 — and anything else is refused rather than mangled. The modulus is 67108859, the largest prime below 226: the round function squares its argument, and a double holds integers exactly only to 253, so a larger modulus overflows into a region where a product has no fractional part and the round function silently returns 0 forever. Decryption is a guard pair: ShakeDecrypt aborts on a bad tag, ShakeDecryptOr hands back a default, ShakeVerify asks on its own. ShakeEncrypt ShakeDecrypt ShakeDecryptOr ShakeVerify ShakeChecksum ShakeModulus ShakeRounds ShakeWrap ShakeIsField ShakeAllField. An obfuscation layer, not a cryptosystem: too few rounds, a key schedule that is a bare rotation, and a checksum that catches accidents rather than forgeries. Includes seq.shoddy.

Appendix A. The concatenative core

The compilation target is itself a legal, complete language: Joy with BASIC vocabulary and layout. Every word is a pure Stack → Stack function; composition is juxtaposition. (This appendix is the law; the tutorial companion — worked traces, the stack drawn after every word — is The Stack.)

Def Fact            Rem ( n -- n! )
    Dup 0 =
    If Then
        Drop 1
    Else
        Dup 1 - Fact *
  • Items on a line execute left to right; lines top to bottom.
  • If (optionally If Then) ends its line, pops a Boolean, and runs one of the two indented branches — sugar for [ then ] [ else ] Ifte. Tokens before If on the same line execute first: Dup 0 < If Then.
  • Take a, b, c pops into immutable named bindings (topmost value goes to the rightmost name) — the escape hatch from Swap Rot Dup shuffle-hell, cf. Factor’s :>.
  • [ ... ] quotes code without running it. Combinators (Map, Fold, Call, Ifte, …) execute quotations.
  • A quotation of literals doubles as a list (Joy-style homoiconicity); the typed surface’s { } lists compile to exactly this.
  • Stack-effect comments Rem ( a b -- c ) or signatures Def f ( a b -- c ) document each word, and the weave-time linter checks call sites against the declared arity (see The linter).

Appendix B. Design notes

  • Why no sigils? a%/a# were the type system of a language without declarations; As types make them a second, contradictable spelling of the same fact, and no sigil exists for List Of t or a generic return. ! (mutation, in the Scheme/Ruby reading) is banned by semantics — reserving it is the most purely functional decision available.
  • Why layout-as-quotation? Indented branches compile to quotations. Newcomers read structured BASIC; the machine sees Joy. Nobody has to know.
  • Why keep the core exposed? Point-free pipelines (data Filter(p) Map(f) Fold(z, g)) are often the clearest notation, and the desugaring rules stay honest when the target is a language you can actually write.
  • Line numbers existed for editing and goto; both are gone.
