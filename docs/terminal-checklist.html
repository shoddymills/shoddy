Terminal checklist

What each mill asks of a terminal window, and which terminals pass

A Shoddy program runs in a terminal window of the operating system's own: under mill run, and under the debugger, where the VS Code extension opens that window rather than using the editor's integrated terminal (VS Code, section 3). This page is the record behind that rule. It lists, per mill, what the program asks of the terminal it runs in, and holds the result of trying each terminal. Run it before a release, on each platform the release names, and write the result and the date into the table.

How to run it

  1. Build the mill and the library: ./build.sh build (./build.ps1 build on Windows).
  2. For each mill below that reads the keyboard or draws with escape sequences, open the terminal named by the column and run the mill from its own folder: ./build.sh run in mills/NAME runs it exactly as the extension's Run button does.
  3. Press F5 on the mill's main file in VS Code as well, so the window the debugger opens is the one tried, with a breakpoint set somewhere the program reaches after reading a key.
  4. Try every item in the mill's “What to check” cell. A terminal passes when every item behaves; otherwise write what failed.

What terminals differ on

The items above are the ones that have differed between terminals, or between a terminal and an editor's integrated one. Each is a question the table answers for a named terminal rather than a claim about it.

  • Keys that belong to the host. An editor's integrated terminal keeps F1, F5 and chord prefixes for itself; a program never sees them. A terminal of the operating system's own may keep some too (a tab key, a search key). The check: the keys the mill names reach it.
  • Cursor-key sequences. The arrow keys arrive as sequences, and which sequences depends on the terminal's cursor-key mode; EvalKey recognises the application-mode ones.
  • Esc on its own. A terminal that waits to see whether an ESC byte starts a sequence delays a bare Esc. The check: Esc quits without a noticeable wait.
  • Size. A game that draws a fixed grid needs the window at least that size, and a terminal that opens smaller scrolls it.
  • Unprinted escapes. A terminal that does not understand a sequence prints its bytes. The check: nothing appears as raw ESC[ text.
