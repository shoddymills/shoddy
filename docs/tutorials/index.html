Tutorials

Start here — build something end to end, by hand or with an assistant

Two tutorials, and they answer different questions. The first is how do I build a Shoddy program? — from an empty folder to a tested, debuggable, runnable thing. The second is how do I get shippable code out of an AI assistant? — a method and a set of templates, for when the typing is the least of the work.

Before either one: install the VS Code extension. It carries a complete toolchain inside it — a compiler and every library — so it is the whole install. Setup, Track A is two steps and needs only the .NET 10 runtime.

Your First Mill

From an empty folder to a spirograph — about half an hour

Build a turtle that draws a colour spirograph, then turn it into a real program: a pure core that computes the drawing as data, a thin shell that puts it on screen, a test that runs without a window, and build scripts that work on anyone's machine. Along the way you meet the ideas that make Shoddy what it is — values that never change, Fold where a loop would be, records and their accessors — plus a debugger session and the mistakes every newcomer makes, with what the toolchain says about each.

Assumes no Shoddy. The finished program ships in the repository at tutorials/spiro/, and its tests run in every build, so the code on the page is code that still works.

Building with an AI

From requirements to shippable code — a method, and blank templates

An assistant can write Shoddy faster than you can type it, which is the least interesting thing about one. This is about the rest: writing a brief instead of a chat message, demanding a plan before any code exists, stating acceptance as tests you wrote, and letting the toolchain rather than your own optimism decide whether it works. It comes with copyable templates — a brief, a fact sheet to hand over, a test skeleton, a verification checklist, a definition of done — and an honest chapter on how this way of working fails.

Bring your own project; the templates have slots for it.

Tip Before either of those, Grounding an Assistant is the five-minute setup: a standing instructions file Copilot or Claude reads by itself, then worked examples — one small program, the prompt you would type for each next step, and the Shoddy that comes back.

After the tutorials

The Beginner's Guide is the systematic tour of the language, chapter by chapter, ending in a program that keeps its data on disk. The machines catalog is the library — graphics, sound, statistics, neural networks, keyed files, linear programming. The mills are complete programs with a write-up each, built the same way the first tutorial builds yours. And Errors & Warnings catalogs every message the toolchain can produce, with the cause and the fix beside it.

Named for the shoddy mills of the West Riding: Useless Things Made Useful Through Skill (the full story).
