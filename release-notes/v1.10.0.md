The runtime stack: a Shoddy program can now hand a live interpreter to
whoever is sitting in front of it. `cuttle` is the stack, `reckoner` is
the engine, a seed file bridges each machine into it, and `halifax` is
the calculator built on all of it — where a session can open a file,
work an indexed table, draw, chart, play a tune and fetch a URL, and
undo any of it.

## Added

- **`machines/cuttle.shoddy`** — the runtime stack. Numbers, strings,
  booleans, lists, quoted programs, pairs, money and matrices as one
  `Cell` type, with the arithmetic that dispatches on their kinds.
- **`machines/reckoner.shoddy`** — the runtime engine: an interpreter
  for whitespace-tokenized RPN lines over a dictionary of registered
  words. Literals, list literals, quoted programs, user-word definition,
  registers, mode words, `UNDO`/`REDO`, a `TRACE` mode, an
  adding-machine tape, `HELP` and `WORDS`, and the combinators that run
  a quoted program back through the same evaluator. Evaluating a line is
  a pure function from one state to the next, which is why undo falls
  out of the semantics rather than being built.
- **`machines/seeds/` — a seed file for every machine in the tree that
  can have one.** A seed registers a machine's words into a reckoner
  dictionary, converting types at the bridge, so a mill pays only for
  the domains it folds. Every one of them is documented, tested, and
  guarded: nothing a session can type ends the session.
- **`mills/halifax`** — a programmable RPN calculator on that stack.
  Everything a programmable calculator wants was already in the tree, so
  the mill is the shell and nothing else.
- **`machines/bool.shoddy`** — bitwise and base conversion: `HEX`,
  `BIN`, `BITAND`, `SHL`, `XOR` and the rest.

### New builtins

All guarded twins — each is an existing word with its failure
*reported* instead of fatal, which is what lets a bridged word exist at
all. See [the spec](https://shoddymills.github.io/shoddy/spec.html) and
[QUICKREF](https://shoddymills.github.io/shoddy/quickref.html).

- `TryReadFile(path)` → `Result` — `ReadFile` that reports failure. The
  only way to ask whether a path can be read: `FileExists` answers
  False for a directory and True for a file you cannot open.
- `TryDeleteFile(path)` → Boolean, and `TryBOpen(path)` → `Result`.
  `TryBOpen` opens an **existing** file only — `BOpen` is open-or-create,
  so a failed *read* left an empty file behind and the question damaged
  its own answer.
- `NetAllowed()` → Boolean, deliberately not gated: every other socket
  word aborts when the network is off, so without this nothing could
  tell "no network" from "no answer" without ending the run.
  `TryTcpConnect(host, port)` and `TryTcpRequest(host, port, secure, msg)`
  → `Result`. The second guards a **whole conversation** — connect,
  optionally secure, send, read to the end, close — because `TCPSend`
  and `TCPRecv` die eight ways between them and a caller composing
  guarded parts would leak a socket on whichever path it missed. It is
  also the only network read that cannot hang: a poll-until-closed loop
  never returns against a keep-alive peer.
- `TryScribblerOpen(w, h)` → `Result`, with `ScribblerOf(n)` and
  `ScribblerShut(n)`. These reach a window by *slot number*: a
  `Scribbler` is its own value kind and cannot be carried by an integer,
  which is what holding one in a named table requires. An ordinary
  program never sees a slot.
- `SoundQueued(ch)` → the milliseconds already queued ahead on a
  channel. `SoundQueue` refuses more than five minutes queued, and
  nothing could see that coming; its own message says to "feed long
  scores incrementally", which was impossible without this.

## Changed

- **`machines/buzzer.shoddy` gains `TryMmlNotes` and `TryNoteMidi`** —
  the same answers as a `Result` rather than an abort, with `MmlNotes`
  and `NoteMidi` now *defined over* them. The first guarded twins at
  machine level rather than in the runtime, and there because a
  malformed score should be reported to whoever typed it. One set of
  rules, not a parser and a validator that drift apart.

## Fixed

- **`mills/tally` now runs from its own folder, like every other mill.**
  Its three shipped specs named their data repo-root-relative, so
  `./build.sh run files/grades.spec` failed from inside `mills/tally`
  with `NO SUCH DATA FILE`. Its suite ran from the repo root while its
  run target ran from the caller's directory, which is why nothing
  caught it. `mills/weather-glass` had the same latent fault in its
  suite. Both now run from the mill folder, and both wrappers' own
  documentation — which had been describing the corrected form all
  along — is true again.
