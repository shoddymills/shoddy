A Windows tooling fix: `build.ps1 all` — the release gate itself — could
not survive being run from anything that captured its output.

## Fixed

- **Every PowerShell script treated an informational line on a native
  program's stderr as a fatal error, but only when the caller captured
  its output.** Windows PowerShell 5.1 wraps each stderr line a native
  program writes in a `NativeCommandError` record whenever the caller
  redirects or captures the script's streams — `./build.ps1 all 2>&1 |
  tee log.txt`, a CI step, an assistant's shell — and under
  `$ErrorActionPreference = 'Stop'` that record is terminating. So the
  run died on a line that was never an error and on a program that
  exited 0.

  It bit `build.ps1 all` in particular: `all` begins with `clean`, which
  wipes `machines/bin`, so the very next mill printed `machine seq.shoddy
  is not built - building` on stderr and the release gate stopped there.
  Run straight into a console the identical command was fine, which is
  why it went unnoticed — and `build.ps1 test` on a warm tree never
  reproduced it, because mill only writes that notice when a machine
  actually needs building.

  Native calls are now run with `$ErrorActionPreference` neutralised for
  their duration and judged on their **exit code** alone, which is the
  only honest signal a native program gives. `'Stop'` stays in force
  everywhere else, where it is doing real work: a `Copy-Item` that fails
  during `stage` must still stop the run rather than package a broken
  `.vsix`. The pattern is the one `scripts/shoddy-release.ps1` already
  used for its `git` calls, applied to the places that had been missed —
  `build.ps1`, `scripts/mill-common.ps1`, all twelve `mills/*/build.ps1`,
  and both release scripts' remaining bare `git` calls.

- **`scripts/shoddy-feature.ps1 ship` could die mid-flight for the same
  reason.** Its `git push` and `git merge` calls were deliberately not
  routed through the `G` wrapper, because it inspects their exit codes to
  give a tailored message — but that left them bare, and `git push`
  writes its progress to stderr every single time. It now uses a
  reporting twin of `G` that neutralises stderr without swallowing the
  exit code.

- **`build.ps1 run` and `build.ps1 weave` reported success for a program
  that had failed.** Neither propagated `$LASTEXITCODE`, so a `.shoddy`
  program that mill exited 1 on came back as 0 — every mill's own
  `build.ps1` already got this right, and the repo's own script did not.
