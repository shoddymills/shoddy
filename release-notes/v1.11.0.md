Regular expressions that cannot hang, sparse matrices and integer
programming under the simplex solver, four new string builtins that make
character access honest and `Split` linear, and a language surface where
every builtin is finally documented in the machine whose domain it
belongs to.

## Added

- **`machines/regex.shoddy`** — regular expressions as a compiled value.
  `RxRead` parses a pattern, compiles it to an instruction program and
  answers `Ok(prog)` or `Err(why, at)`; every match word takes the
  program, never a string. The engine is a **Pike VM** — Thompson's
  construction run as an ordered thread list with capture slots — so it
  **never backtracks** and its cost is bounded by pattern size times
  subject length: `(a|a)*b` against thirty `a`s returns at once, where a
  backtracking engine is still going. **Nothing in the file aborts**: a
  malformed pattern is an `Err`, an absent match a `None()`, and there
  is not one call to `Error` in it. The price of the guarantee is
  refused *by name at its offset* — no backreferences, no lookaround, no
  atomic or possessive forms, no named groups.
- **`machines/sparse.shoddy`** — matrices that are mostly zeros, stored
  by column. Column-major because its reader reads down: revised simplex
  prices a column at a time and never wants a row. Shapes are refused at
  construction rather than at read, and a cell summing to zero is not
  stored at all.
- **`machines/mip.shoddy`** — integer programming by LP-based branch and
  bound over the simplex solver. Depth-first, most-fractional branching,
  every node re-solved from scratch and pruned on the incumbent bound.
  The search is **one self-recursive word** with the second child in
  tail position, so live depth is the tree's depth and not its node
  count. **No shadow prices on a `MipSolution`** — the last node's LP
  duals are not the integer problem's sensitivities; `MipFixed` pins the
  integers where the search left them and hands back the LP whose duals
  *are* meaningful, so the refusal is a door and not a dead end.
- **`machines/terminal.shoddy` and `machines/lineshaft.shoddy`** — two
  machines that **declare no words**, which is new for this tree and is
  the point rather than an oversight. They are where the runtime's
  homeless builtins are finally documented: `Print`, `Input`,
  `InputLine`, `InKey` and `Args` in the first, `Call`, `Ifte`, `Error`
  and `Assert` in the second. Both are callable with no `Include` at
  all. A *line shaft* carried power from a mill's engine out to each
  machine by belt, which is what `Call` does between the `Engine` and a
  quotation.
- **Reckoner seeds for the new machines** — `seedregex`, `seedsparse`
  and `seedmip`, so a `halifax` session can state a linear program, ask
  for a whole-number answer, and test a pattern, without writing a
  program.

### New builtins

Four, all about reading characters, and the first three exist because
the obvious way to read one was a trap. See
[the spec](https://shoddymills.github.io/shoddy/spec.html) and
[the quick reference](https://shoddymills.github.io/shoddy/quickref.html).

- `CodeAt(s, k)` → the code of the character at position `k`. It
  **refuses** past the end, where `Mid` trims. That is the whole reason
  for it: `Asc(Mid(s, k, 1))` reads the wrong character and then aborts
  naming `Asc`, a word away from the index that was actually wrong, and
  only on inputs long enough to reach the end.
- `Codes(s)` → every character's code as an `Array Of Number` in one
  pass, so a scanner indexes in O(1) instead of walking. `FromCodes` is
  its exact inverse, **NUL included** — which `Chr` cannot build, since
  `Chr(0)` is the empty string.
- `InstrFrom(s, sub, from)` → `Instr` begun at a position, without
  copying the subject to get there.

## Changed

- **`Split` and `Replace` are linear in their subject.** Both used to
  recurse on a copy of the tail — because `Instr` can only search from
  the beginning, splitting into *n* fields copied the subject *n* times,
  and the most-used word in the library was quadratic. They carry a
  position and call `InstrFrom` now: the same answers, in linear time.
  `xml.shoddy`'s scan got the same treatment. `Replace` is *not* linear
  and its comment says so — what remains is the `&` chain, which is a
  different change.
- **Every builtin is now documented in the machine that owns it.** All
  161 of them are partitioned one owner each, and 142 documentation
  blocks sit in the machine whose domain they belong to — `Left` in
  `str.shoddy`, `BOpen` in `recio.shoddy`, `Sort` in `seq.shoddy` — in
  the source and on the doc page, with `spec.html`'s flat reference
  linking each entry to its owner. Nobody reads a flat reference to find
  a builtin they do not know exists; `str.shoddy` never mentioned
  `Left`, `Right` or `Mid` in its own source until now.
- **`mps.shoddy` reads a `BOUNDS` section.** In the `A x >= Rhs` frame a
  bound *is* a row, and a single-entry one: `LO`, `UP`, `FX`, `BV` and
  `PL` are read and reported under `NAME.LO` / `NAME.UP`. `MI`, `FR` and
  a negative `UP` are still refused — each lets a variable go negative
  and breaks the frame every word there assumes. Integer `MARKER`s are
  read and answered only by the Mip words.
- **Assembly is sparse throughout the solver.** A COLUMNS section is
  already a triplet list, so it is built as one and the dense words
  answer through a conversion at the door. On BLEND that is 789 stored
  numbers instead of 9711 cells, and **not one bit of the answer
  moves**: same 117 pivots, same cost, same duals, verified against the
  pre-change machines built from the previous tag.
- **The AI grounding pages are rebuilt around pointers rather than
  copies.** [Grounding an Assistant](https://shoddymills.github.io/shoddy/assistants.html)
  and [Building with an AI](https://shoddymills.github.io/shoddy/tutorials/with-ai.html)
  now separate the *shape* of the language, which is written out because
  an assistant cannot look up what it does not know it is missing, from
  the *specifics*, which are pointed at because a copied word list is
  wrong the moment a machine gains a word. The machine list they used to
  carry is gone; they name the directory instead.
- **Machine and mill pages share one prev/all/next ribbon**, rebuilt
  from each index page's order rather than from directory order — which
  fixes the links that order produced.

## Fixed

- **An operator written hard against a name is caught where it is
  written.** Words split on whitespace, so `count+1` was one long name
  and the failure surfaced somewhere else entirely. An operator
  character mixed into a word carrying a letter or digit is now an error
  at that word, and the fix is a space. Number literals are exempt, so
  `1E+10` is still a number.
- **A line whose brackets are still open is gathered onto the next one**
  at the `halifax` prompt and in `LOAD`, instead of being refused a line
  at a time.
- **A `Case` pattern's constructor counts as a use of the machine that
  declares it**, so the doc gate no longer reports a machine as unused
  because the only thing naming it was a pattern match.
- Two `Include`s that nothing had used for some time are gone.
