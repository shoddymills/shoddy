Shoddy is a purely functional BASIC, compiled the whole way down to .NET. This
release retires the project's headline future-work item: the mill now carries
a **weave-time linter with stack-effect inference**, on by default — and a new
**errors reference** documents every message the toolchain can raise, with
broken and fixed code side by side.

## The linter

Every `mill run`, `weave`, and `machine` build now checks the parsed program
before anything executes:

- **Net stack effects.** Every `Def` must yield exactly one value, or none —
  computed by depth simulation, so concatenative bodies check the same way as
  applicative ones, and recursion (plain, mutual, or void) grounds through a
  fixpoint.
- **Branch agreement.** Every `If` and `Select Case` arm must leave the same
  number of values. A branch that stops the program (`Error`) is understood
  to diverge, so the strict-conversion idiom stays silent.
- **Call-site depth.** Calls are checked against declared arities — including
  calls into precompiled machines, whose manifests now carry each word's
  stack effect.
- **The sharp edges, named.** An operator called function-style
  (`Mod(a, 2)`, `-(x)`) is a *section* — a function value — and the linter
  says so when one flows into a numeric slot. A bare name auto-quoted in
  argument position that resolves to nothing is almost certainly a typo. A
  line beginning with a stray `And`/`Or` grabbed a value it shouldn't. A
  number matched against sum-type constructors can only ever fall to
  `Case Else`. A mid-body `Let` shadowing a field accessor the program reads
  computes wrong answers silently. Each gets a warning that names the fix.

Doctrine: **warnings, never errors** — on stderr, never the exit code — and
**only on the provable**: anything the checker cannot model is skipped, not
guessed. `--no-lint` silences the warnings; `--lint-verbose` reports
coverage. The one exception is an **unknown word**, which is now a weave
error no flag overrides: nothing legitimate survives resolution without a
meaning, and the same program used to die at runtime with less context.

The linter drew blood before it ever shipped: `NormPdf` in the stats machine
had crashed on every call since it was written — its `-(z * z)` was a
section, not a negation — and the sweep that cleaned the repository for the
linter's arrival was itself caught twice by the linter mid-cleanup. The full
story is in the commit history; the fixes are in this release.

## The errors page

[A new reference](https://shoddymills.github.io/shoddy/errors.html), with its
own tab in the header: **every message the toolchain can raise**, in four
voices — setup and environment first (the missing .NET 10 runtime, the
SDK-versus-runtime split, a stale `SHODDYLIB`), then weave errors, lint
warnings, and runtime errors. Sixty-two diagnostic cards, each with its
message, a plain-language cause, and broken code beside the fix. Written for
novices; kept honest by a checker that asserts every diagnostic string in
the sources appears on the page.

## Sturdier machines

- **Machine DLLs rebuild themselves.** A machine whose `.shoddy` source (or
  whose dependency's DLL) is newer than its own DLL is rebuilt in place
  before loading, with a one-line note. An edited machine can no longer be
  silently shadowed by yesterday's build.
- **Re-export includes survive compilation.** A machine that includes
  another purely to pass its words along (isam's `seq`) used to lose that
  dependency in the compiled DLL — Roslyn drops unused assembly references —
  stranding programs that relied on the transitive surface. Manifests now
  declare their include chain explicitly.

## Fixed

- `NormPdf` (stats) computes instead of crashing — the linter's first catch.
- A latent crash in mungo-caverns' hint logic on paths the test harness
  never walks — the linter's third catch, minutes after its second.
- Eighteen shadowing hazards across the machines and mills — mid-body `Let`s
  named after record fields their programs read — renamed away.

## Install

The VS Code extension carries its own mill and the whole machine library, so
it is the entire install. Grab the `.vsix` below and:

```
code --install-extension vscode-shoddy-*.vsix
```

The only prerequisite is the [.NET 10 runtime](https://dotnet.microsoft.com/download/dotnet/10.0)
— the runtime, not the SDK. Upgrading from 1.1.x: install over the top; your
settings survive. If a program of yours now prints lint warnings, they were
earned — each names its fix, and `--no-lint` restores the old silence.
