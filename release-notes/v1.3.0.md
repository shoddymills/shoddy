Shoddy is a purely functional BASIC, compiled the whole way down to .NET.
This release adds no language, compiler, or library changes — the mill
behaves exactly as it did in 1.2.0. What it adds is **a third tutorial that
asks you to write no Shoddy at all**, and **a statement of authorship** that
now travels inside the extension.

## Backgammon, by Specification

[The third tutorial](https://shoddymills.github.io/shoddy/tutorials/backgammon.html)
is the method under load. Thirty-one steps build a complete backgammon
program in two phases: an engine that never learns a screen exists — the
rules, the doubling cube, judgement, and a network that learns to play from
self-play — and then a board you can sit down at.

Every prompt is on the page, ready to copy. Each step states what the model
must deliver, what to reject, and the gate its tests have to answer to. You
write none of the Shoddy: not the engine, not the game, not the tests. What
you write is what must be true.

It is also a fair test of the idea, because there is no backgammon engine in
Shoddy for a model to have memorised — every line has to come from the
requirement. And it is honest about its own standing: unlike everything else
on the site, this program has not been built end to end, and the page says so
in its first panel.

## Authorship, and the record

[Authorship](https://shoddymills.github.io/shoddy/authorship.html) states who
designed and owns Shoddy, which tools were used and how, what is claimed and
what deliberately is not, and the legal position behind it — creative
direction, selection, arrangement and revision as the basis of the claim, and
the abstract rules of the language as a method of operation anyone is free to
implement.

The [Devlog](https://shoddymills.github.io/shoddy/devlog.html) is the record
it rests on: the conversation in which the language was invented, specified
and built, with the designer's messages reproduced verbatim, typos and all.

`AUTHORSHIP.md` now ships **inside the `.vsix`**, alongside the licence and
the third-party notices. The package is the whole install for most people and
never sees the repository, so the disclosure travels with it.

## The site

- **Two-row navigation.** Fourteen items in one row wrapped raggedly at any
  width. Heritage and Authorship now ride beside the wordmark, right-
  justified; the remaining twelve spread the row beneath. The item formerly
  called *Story* is now **Heritage**, matching the page it opens.
- **Every image responds to the pointer.** The lift the gallery cards always
  had now applies to catalog thumbnails, cross-reference icons and masthead
  icons too — with keyboard focus states, and movement suppressed for readers
  who ask for reduced motion.
- **Pages describe themselves.** Six mastheads carried the tagline where a
  description belongs; they now say what the page is, and the search-result
  text matches.
- **Link text that means something.** Roughly fifty links to the heritage
  page read "the full story", "the story is here", or the bare filename.
  They now name their destination.
- **Building with an AI** gets an animated icon: a question typed to an
  assistant, the Shoddy that comes back, and the output it produces — the
  exchange taken verbatim from *Grounding an Assistant*, compiled and run
  before it was drawn.

## The repository

- **The README documents the documentation.** It listed four pages against a
  site of fourteen; it now covers them all, grouped by what you came for,
  plus a section pointing at Discussions, Issues and Releases. `release-notes/`
  is this project's changelog and the README finally says where it is.
- **`CONTRIBUTING.md` no longer promises a CLA bot** that was never
  configured. Inbound=outbound MIT and the DCO were already stated directly
  above it, so nothing is lost and a first-time contributor no longer meets a
  step they cannot complete.
- **`verify-docs.js` checks the whole nav**, not just the first row of it.

## Install

The VS Code extension carries its own mill and the whole machine library, so
it is the entire install. Grab the `.vsix` below and:

```
code --install-extension vscode-shoddy-*.vsix
```

The only prerequisite is the [.NET 10 runtime](https://dotnet.microsoft.com/download/dotnet/10.0)
— the runtime, not the SDK. Upgrading from 1.2.x: install over the top; your
settings survive, and no program that compiled before will compile
differently now.
