Four new machines and one rename that will break programs. Read the first
section before you upgrade.

## Breaking

- **`machines/crypto.shoddy` is now `machines/shaker.shoddy`, and every one of
  its words is renamed** — `CryptEncrypt` → `ShakeEncrypt`, `CryptDecrypt` →
  `ShakeDecrypt`, `CryptDecryptOr` → `ShakeDecryptOr`, `CryptVerify` →
  `ShakeVerify`, `CryptModulus` → `ShakeModulus`, `CryptRounds` →
  `ShakeRounds`, `CryptIsField` → `ShakeIsField`, and the internals with them.
  A program that includes `crypto.shoddy` or calls any `Crypt*` word will not
  compile. The fix is mechanical: change the include, then `Crypt` → `Shake`.

  The rename is the point rather than a side effect. That machine's header has
  always carried a section saying, at length, that it is an obfuscation layer
  and **not** a cryptosystem — four rounds is far too few, the key schedule is
  a bare rotation, and anyone who wants to read your data will read it. Every
  word in it was nevertheless spelled `Crypt`. A name with *crypt* in it
  promises secrecy; the documentation underneath withdrew the promise. Now the
  name doesn't make it.

  It is named for the first machine in a shoddy mill: a rotating drum, slatted
  or spiked, that tumbled incoming rags to beat the dust and grit out through a
  grating. It did not change what the rags were — it rearranged them, shook out
  what shouldn't be there, and passed the same material on.
  [The shaker page](https://shoddymills.github.io/shoddy/machines/shaker.html)

## Added

- **`machines/json.shoddy`** — JSON to RFC 8259, both directions. An object's
  members *are* [dict](https://shoddymills.github.io/shoddy/machines/dict.html)'s
  association list, so `JGet` and `JPut` are `DictGet` and `DictPut` in a hat.
  `JsonRead` is total — `JOk` or `JErr` with a reason and a 1-based offset —
  because Shoddy has no catchable errors and a parser that could only abort
  would be unusable on input you didn't write. Compact and pretty writers,
  `JsonCanonical` for stable ordering, and `JEqual` for deep comparison.
  [json](https://shoddymills.github.io/shoddy/machines/json.html)

- **`machines/xml.shoddy`** — XML 1.0, well-formed, both directions. Elements,
  attributes, text, comments, processing instructions, CDATA and the doctype,
  all kept, so a document that goes in comes back out rather than a paraphrase
  of it. Attributes are an association list, as json's members are. The doctype
  is carried whole and never read, which is what makes the billion-laughs
  expansion impossible. Namespaces are carried literally, not resolved.
  [xml](https://shoddymills.github.io/shoddy/machines/xml.html)

- **`machines/html.shoddy`** — HTML, forgivingly, **built on xml and reusing
  its tree outright**. There is no `Html` type: a parsed page *is* an `Xml`, so
  `XFind`, `XPath`, `XTextOf` and `XEqual` work on it and `html` redefines none
  of them. It handles what hand-written pages are actually like — missing end
  tags, uppercase names, unquoted and valueless attributes, a stray `<` in the
  prose, a `<script>` full of characters that would otherwise be markup. It is
  **not** the HTML5 tree-construction algorithm, and its header says so at
  length.
  [html](https://shoddymills.github.io/shoddy/machines/html.html)

- **`machines/shaker.shoddy`** — reversible obfuscation: a four-round Feistel
  network over a `List Of Number`, keyed by another, with a checksum appended
  so tampering is detectable. For keeping a save file out of a text editor.
  Not for keeping secrets — see Breaking, above.
  [shaker](https://shoddymills.github.io/shoddy/machines/shaker.html)

- **`tst/html-demo.shoddy`** — reads every page of this project's own
  documentation and reports dead links, anchors pointing at ids that don't
  exist, ids used twice on a page, and images that are missing or have no
  `alt`. It found a real defect on its first run: a machine page that was
  listed in the catalog, on the home page and in the sitemap, and unreachable
  by paging, because two of its neighbours agreed with each other and not with
  it.

## Changed

- The machines catalog gains a **Markup & data formats** section holding json,
  xml and html. `json` moved there from Data & storage.
- The library is **26 machines**. The previous/next chain through the catalog
  has been verified to reach all of them, in both directions.
- `mungo-caverns` no longer advertises a transcript sweep it cannot run. The
  C original's ~107 recorded games were never redistributable and everything
  they graded is now embodied in the mill's five Shoddy test suites; the
  harness and its build targets are gone, and the 107/107 grading is recorded
  as the history it is.
- The conduct and security contact address is now `stephen@shoddymills.dev`.

## Fixed

- The `net` machine page was unreachable by paging through the machines
  catalog — listed everywhere, but the previous/next links of the pages either
  side of it agreed with each other and skipped it.
- `docs/guide.html` was the one place that never learned about newly added
  machines; both of its lists are now generated against the same ground truth
  as the rest of the site.

## Notes for anyone reading the sources

Two properties of the runtime became load-bearing while these machines were
written, and both are documented in `machines/xml.shoddy`:

- **File I/O is Latin-1** — one byte in the file is one character in the
  string, which is what lets the same words read a PNG. So a character
  reference has to decode to its **UTF-8 bytes**, not to `Chr(codepoint)`;
  otherwise the same character written two ways is two different strings, and
  `WriteFile` turns anything above 255 into a question mark.
- **`Trim` strips spaces only** — not tabs, not newlines. Markup is mostly
  made of those, so xml carries its own `XIsBlank` and `XTrimWs`.
