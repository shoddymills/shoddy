Four machines and one language change. Absence and failure are now the
language's own — `Some`, `None`, `Ok` and `Err` need no `Include` — and the
numbers shelf gains finance, engineering mathematics, linear algebra and
symbolic algebra. One rename in `str` will break programs; it is one line
per call site and the compiler names every one.

## Breaking

- **`str`'s `Bool` and `BoolOr` are now `ToBool` and `ToBoolOr`.** A
  program that reads a boolean out of text will not compile until it is
  renamed:

  ```
  unknown word: BOOLOR
  ```

  Why: `BoolOr(s, fallback)` read as a logic gate and was in fact a parser —
  "parse `s`, or fall back to this" — which is a genuinely misleading name
  independent of anything else. The new spelling matches the number side
  exactly, which is the whole point:

  | | number | boolean |
  |---|---|---|
  | test | `IsNumeric(s)` | `IsBool(s)` |
  | strict | `Val(s)` | `ToBool(s)` |
  | total | `ValOr(s, d)` | `ToBoolOr(s, d)` |

  It also frees the entire `Bool*` prefix, which a machine about bits and
  gates will want.

## The language: absence and failure

Two sum types are now **predeclared**. No `Include`, no declaration:

```
Type Option = Some(Value) | None
Type Result = Ok(Value)   | Err(Why, At)
```

The spec has described `Option` since it was written — *"the language's
answer to NULL: absence is a value you must match, never a hole"* — and the
tree contained exactly one, in `tst/libtest.shoddy`, the file whose job is
to prove features work. Nothing else reached for it, because reaching for it
meant declaring it first.

Meanwhile the library had paid for the gap four ways: twenty-two `*Or` words
each paired with a strict partner that aborts, three different not-found
sentinels across seven places, three separately invented `Ok`/`Err` types,
and `IsNumeric`/`Val`/`ValOr` in the runtime doing what one `Option` would.

**Why not a machine.** Absence over Number, String and Boolean is a
statement about every type, so `seq` would have been claiming it for
sequences — and since v1.6.0 scoping, a consumer of `str` would have to
include `seq` merely to *match* on what `str` returned. A replacement for
NULL that you have to import is not a replacement for NULL.

**Pick `Option` when the only possible reason is "not there"** — a missing
key, no bits set. **Pick `Result` when the caller could act differently
depending on what went wrong.** `At` is `0` when there is no position and a
1-based offset when there is, which is how one `Result` serves both a parser
and a rule boundary.

**They generate no accessor words, deliberately.** There is no `Value(o)` to
reach past the check with. An accessor on a sum type is partial: were it a
word, `Value(None())` would compile and then die at run time with *"None has
no field Value"* — reopening the exact hole the type exists to close. Pattern
binders are positional and named at the match site, so `Case Some(x)` already
hands you the value and an accessor could only offer a way to skip the match.
`Select Case` is the way in, and the only one.

Declaring your own type named `Some`, `None`, `Ok` or `Err` is now a
duplicate-definition error.

Two words take up the offer immediately: `str.ToBoolOpt` — the primitive that
`ToBool` and `ToBoolOr` are one-liners over, because neither can be built
from the other — and `seq.IndexOpt`, beside an `IndexOf` that keeps its `0`
because too much already reads it.

## Four new machines

### fin — money over time

The time value of money, loans and amortisation schedules, investment
appraisal (NPV, IRR, payback, MIRR), everyday small-business arithmetic, the
four depreciation methods, a civil calendar, and bond pricing with yield and
duration. Rates are decimal fractions per period, everywhere; amounts are
plain numbers in whole currency units.

It deliberately does **not** use `money.shoddy`, which is the obvious choice
and the wrong one: `Money` holds whole cents and has no division, so `FinPv`
— a division by `(1 + rate)^n` — cannot be written in it at all.

### eng — the engineer's calculator

Trigonometry the runtime does not supply and all twelve hyperbolics; complex
numbers with their own type; numeric differentiation, integration,
root-finding and optimisation over quotations; polynomial arithmetic; number
theory; combinatorics and the gamma family; the discrete distributions; unit
conversion where a unit is a *record* carrying its quantity, so a mismatched
conversion aborts rather than happening; and the CODATA constants.

**Angles are radians at every boundary.** There is no degree mode, because a
mode is state, and a trig word whose answer depends on a setting made three
screens ago is the worst thing about the calculators this surface was
compiled from.

### lin — linear algebra over `matrix`

Determinants, inverses, linear systems, echelon forms and rank, the LU, QR
and Cholesky factorisations, characteristic polynomials and eigenvalues.

**The type stays in `matrix`.** That machine owns a data structure and its
arithmetic; `lin` owns the algorithms over it, so a program that only
multiplies matrices does not carry an eigenvalue solver. Include both.

`LinEigVals` finds the **real** eigenvalues only, by bracketing sign changes
of the characteristic polynomial — so the *length* of its answer carries
information, and a 90° rotation matrix correctly returns nothing at all.
`LinEigSym` is the complete answer for a symmetric matrix.

### alg — algebra over expressions

The values here are not numbers but the *formulae* that produce them. An
expression type, a parser and a printer, exact rational arithmetic, a
canonical-form simplifier, symbolic differentiation, expansion and
factorisation, partial fractions, limits, a bounded integrator, equation
solving, first-order ODEs and Taylor series.

**Numbers are exact rationals.** `1/3 + 1/6` is exactly `1/2`, which is what
separates a CAS from a calculator: the moment it is `0.5` the simplifier
cannot recognise zero, factorisation cannot find rational roots, and partial
fractions cannot solve for their coefficients. It is also why the Maclaurin
series of sine comes back as `x - x^3/6 + x^5/120` rather than a decimal
approximation of it.

**And the word that justifies the machine:**

```
Let f = AlgToFn(AlgParse("x^3 - 2*x - 5"), "x")
Print(EngZeroOf(f, 2, 3))            ' 2.0945514815
```

A formula read from a file, a CSV header or a prompt becomes a function
value, and every numeric word in `eng` accepts it unchanged. **Neither
machine includes the other** — a quotation is a builtin type, so they compose
with no dependency in either direction.

`alg` is the first machine built on the new `Result`, and it uses it the way
the type is meant to be used: `Err` there usually means *"outside the
implemented rules"*, which is an ordinary answer about the input rather than
a fault. `Err("IRREDUCIBLE OVER THE RATIONALS", 0)` from `AlgFactor` is
stating a true fact about the polynomial.

## Known limits, stated rather than discovered

Each new machine documents its own boundary on its page, because for this
kind of library the boundary is as much of the documentation as the
capability. The ones worth knowing before you reach them:

- **`eng`**: `EngFact(18)` is the last exact factorial; `EngSinh` and
  `EngCosh` overflow past |x| > 710; the numeric derivative is good to about
  eight digits and the second derivative to four.
- **`lin`**: written for clarity over speed, so it rebuilds a whole matrix
  per elimination step — comfortable to about n = 8.
- **`alg`**: integration is table-driven and says so at runtime through
  `AlgIntegRules()`; factorisation is univariate over the rationals; limits
  are substitution plus bounded L'Hôpital, so a limit that depends on the
  *side* of the approach is refused rather than guessed. And `AlgEqual` is
  canonical-form equality, not mathematical equality — `1/(x*(x+1))` and
  `1/(x^2+x)` are the same function and are not `AlgEqual`, because the
  canonical form neither factors a denominator nor expands one.
