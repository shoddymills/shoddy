The v2.0.0 release page published no assets: the Release workflow failed
on defects that only a clean Linux runner could surface. This patch fixes
all three and ships what 2.0.0 promised — the extension, and one sparky
archive per OS. Nothing in the language changed.

## Fixed

- **The mill could not be found off Windows.** Every host and proof
  project pinned `ShoddyToolPath` to `bin\mill.exe`; `dotnet publish`
  names the apphost plain `mill` everywhere else, so the MCP lane — and
  the release itself — died on Linux with `mill.exe: not found`. The pin
  is now OS-conditional in all eight projects.
- **Two projects weaving one mill could crash the build.** ShoddyWeave
  runs the mill once per referencing project, and parallel MSBuild runs
  them together — `File.Create` on the same output from two processes
  killed whichever lost. It struck the MAUI lane in CI and the sparky
  solution locally, both intermittently. The mill now serializes writers
  per target with a cross-process gate; distinct targets never contend.
- **The proof suite pinned the Windows mill too.** `ProofTests` passed
  `bin\mill.exe` to the scaffolded template builds by name, so the whole
  proof collection failed on Linux; it now asks the OS. And the suite ran
  before the mill was built, so on a clean runner its publish-it-myself
  fallback ran inside `dotnet test` on a cold cache — a half-hour stall.
  The build targets now build the mill first, making the fallback a
  no-op.
- **The headless weave proof could not see the machine library.** The
  headless mill runs from `artifacts/bin/`, where no `machines/` sits
  beside it, so a seed's bare `Include "cuttle.shoddy"` had nowhere to
  resolve once source splicing began. The CI job now pins `SHODDYLIB` to
  the checkout's own machines — the exact case the variable exists for.
