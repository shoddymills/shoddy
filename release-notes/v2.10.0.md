## Added

**The debugger, rebuilt.** Press `F5` on any `.shoddy` file, as before,
and you now get:

- **The program's own terminal window.** The program runs exactly as it
  does under `mill run`: in a window of the operating system's own
  terminal (or the one `terminal.external.*` names), with that window's
  keyboard and screen. `Input`, `InputLine` and `InKey` work, the arrow and
  function keys reach the program instead of VS Code, and VT100 games play
  at full size. Scribbler windows and sound work as they do outside the
  debugger.
- **Breakpoints in machines.** Set a breakpoint in `seq.shoddy` or any
  other machine and it stops there. Step into goes into a machine's Defs
  too.
- **Conditional breakpoints, hit counts and logpoints.** A condition is
  any Shoddy expression; a hit count takes a number, a comparison or
  `% N`; a logpoint writes `n is {n}` to the Debug Console without
  stopping.
- **A stop at any runtime error**, at the failing line, with every frame,
  local and stack value still there to inspect. Untick *Runtime errors* in
  the Breakpoints view to let errors end the program instead.
- **Pause** (`F6`), including a program stuck in a loop.
- **Values you can change.** Double-click a local, a top-level `Let`, a
  value on the stack, a record's field or a list's element, and set it to
  any Shoddy expression.
- **Expressions everywhere.** The Debug Console, Watch and hover evaluate
  any Shoddy expression in the frame you are looking at: its locals, the
  program's Defs and types, every machine word it included, and the
  builtins.
- **Launch settings** for a `launch.json`: `args` (what `Args()` answers),
  `allowNet` (as `mill run --allow-net`), and `cwd`.

**Mills**

- **thornle**, the five-letter guessing game in the terminal. Six
  guesses, each a whole typed line, and every letter marked in the
  project's three thread colours, or with `[A]` and `(A)` when colour is
  off. A numeric second argument seeds the game so a reported one can be
  replayed. The same game ships as `thornle.halifax`, so you can play it
  with Claude through sparky. See the
  [thornle page](https://shoddymills.github.io/shoddy/mills/thornle.html).

**VS Code**

- **Run File** (`ctrl+r`, the run button, or `Ctrl+F5`) runs the program
  in a terminal window of its own as well, so interactive programs work at
  full size.
- **A program runs from its own folder**, whichever folder the workspace
  is opened on, for `F5` and every command, so a relative path such as
  `files/words.txt` finds the file beside the program. There is one
  terminal per program folder.
- **`F5` starts at once.** The extension ships the compiled library in
  both configurations, so the first debug session after an install no
  longer builds every machine it reaches first.
- The [terminal checklist](https://shoddymills.github.io/shoddy/terminal-checklist.html)
  records, per mill, what each one asks of a terminal and which terminals
  pass.

**Sparky**

- **A native Windows ARM64 build.** The release now carries
  `sparky-2.10.0-win-arm64.zip` beside the other four, so an ARM64 Windows
  machine runs sparky natively instead of under x64 emulation.
- **One-command install from a checkout.** `hosts/mcp/build.sh install`
  (`build.ps1` on Windows) builds sparky for this machine, checks it
  answers, installs it to one fixed place, and registers it with Claude
  Code. Re-running it is the upgrade. See the
  [sparky page](https://shoddymills.github.io/shoddy/mills/sparky.html).

## Changed

- **`F5` with no `launch.json` runs to the first breakpoint** instead of
  stopping on entry. `"stopOnEntry": true` restores the old behaviour.
- **The extension prefers a checkout's own mill**, now found under
  `artifacts/bin/Shoddy.Mill/release/`, and points `SHODDYLIB` at that
  checkout's `machines/`, so a workspace that builds the mill debugs and
  links its own library.
- **For contributors:** every build output lives under `artifacts/`, and
  `./build.sh prove` runs, on your own machine, everything CI and the
  release check, so a pull request fails on your machine before it can
  fail in CI.
