## Fixed

- **For contributors: a build with nothing changed now does nothing.** Two
  causes made every `./build.ps1 build`, and so every `run` and every
  mill's `./build.ps1`, do work on a tree with no edits.
  - The machine-library generator ran on every build, four times: both
    libraries in both configurations. Its MSBuild target named the
    generated C# file as its output, and the generator leaves that file
    alone when its content is unchanged, so the file's timestamp stayed
    behind the inputs and the target never counted as up to date. The
    target's output is now a stamp file touched on every run. The C# file
    is still written only when it changes, so the compiler still skips.
  - Every git commit recompiled every project in both configurations. The
    .NET SDK's Source Link reads the HEAD commit id on each build and
    writes it into every project's generated `AssemblyInfo.cs`, a
    compiler input. Local builds now skip that query. CI, `prove` and
    release builds keep it, so a shipped mill still names its commit in
    `mill --version`. A local mill prints the version with no commit id.
