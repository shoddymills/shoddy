## Added

- **Every documentation page now links back to the repository.** A
  `GitHub` link rides in the header beside Fettler, and the footer carries
  the [MIT License](https://github.com/shoddymills/shoddy/blob/main/LICENSE)
  and the source. The tagline in the footer is itself the link to
  [the heritage of the name](https://shoddymills.github.io/shoddy/heritage.html),
  and the home page's "Two minutes to running" links straight to the
  [latest release](https://github.com/shoddymills/shoddy/releases/latest)
  where it talks about the download.
- `mills/sparky/files/weather-glass.sparky` — the weather-glass forecast
  words (column padding, condition abbreviations, cloud cover, the
  Rothfusz heat index) as a sparky word file the calculator can `load`.

## Changed

- **`./build.ps1 run` takes the mill's own switches** — `--allow-net`,
  `--no-window`, `--no-lint`, `--lint-verbose` — before the file, and
  passes everything after the file to the program through `Args`:
  `./build.ps1 run --allow-net mills/weather-glass/weather-glass.shoddy 63011`.
  An unknown switch is refused with the usage line rather than handed to
  the mill, which would have taken it for the file name. `build.sh` is
  the twin.
- The docs gate (`scripts/verify-docs.js`) now holds every page's footer
  identical, and refuses a footer that has lost its licence or repository
  link — the same way it has always held the nav bar. A link added to one
  page in a hundred and twenty and forgotten on another is a red gate now,
  not a stale page.
- The README's "Two minutes to running" carries the Fettler card the docs
  home page already had.

## Fixed

- `./build.ps1 test` failed in `LibTestWovenAgainstMachines` with
  "Could not load file or assembly 'Shoddy.Machines.Str' … already loaded"
  on any machine where `SHODDYLIB` was set — which the VS Code extension
  does in its own terminal. The test builds its machines in a scratch
  workspace, but the dependency walk searches the machine library first,
  so a library on the path supplied a second copy of the same assembly
  name. The test now clears `SHODDYLIB` for its own run and restores it
  afterwards. CI was never affected; only local runs from an extension
  terminal were.
