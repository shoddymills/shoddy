## Fixed

- **The hosts' own file paths keep to the root.** Sparky's `save`, `load`
  and `tape` tools, and the reckoner app's `SAVE`, `LOAD` and `TAPESAVE`,
  named their file in the host rather than in the engine, so the engine's
  boundary never saw the path: an absolute path was used as given, and `..`
  climbed out. Both hosts now resolve those paths by the engine's own rule,
  through `HostPath` in Shoddy.Hosting, and refuse a path outside the root
  with `... is outside the file root`.

## Changed

- **Sparky's `tape` tool takes `from` and `to`**, counting rows from 1, and
  answers those rows with a closing line saying how many the tape holds. The
  whole tape is still the answer when neither is given.
- **Sparky refuses an argument it does not understand** rather than answering
  something else: `words` with a `by` other than `seed` or `effect`, `canvas`
  with a `surface` that is not a whole number, and `tape` with a `file` beside
  `from` or `to`.
- **Sparky names its root** in the `initialize` instructions and in the
  `save`, `load` and `tape` tool descriptions, so a caller can tell which
  directory a file tool must write to for the session to read it. The
  grounding says that a file already under the root is read with `READFILE`
  or `JSONLOAD` and needs no `put`.
- **The sparky shape grounding is corrected** on three points it had wrong
  since v2.8.0: lists compare item by item, lists are cons cells with O(1)
  `First`, `Rest` and `Prepend`, and any tail call is a jump, mutual recursion
  included.
- **A long string on the stack renders abbreviated**, as a long list always
  has: the first line to the 76-column bound, then `... N more` inside the
  quotes, N counting the characters not shown. The value is untouched; `LEN`,
  `MID` and `=` see every character. This shows at the halifax prompt, on the
  tape, and in every sparky answer. It was added for sparky, whose caller is
  shown the whole stack after every line: a string left at `y:` was resent,
  entire, with every later answer until something dropped it.
- **Sparky carries what a turn prints to 200 lines or 16,000 characters** and
  then says how many lines were left out. The engine still prints everything
  to the session's pen; only what one answer copies is bounded.

## Added

- **`SHAPE`**, a core reckoner word: describe the top cell without rendering
  it. A number with its value; a string by its length, line count and first
  line; a dict by its entry count and its keys with the kind under each; any
  other list by its length, depth and the kind of each of its first twenty
  elements; a pair by its halves; a matrix by its dimensions. It answers in
  words and leaves the stack as it was. `CutShape` in
  [cuttle](https://shoddymills.github.io/shoddy/machines/cuttle.html) is the
  word underneath.
- **`DPATH`**, in [seeddict](https://shoddymills.github.io/shoddy/machines/seeddict.html):
  a path of `STRING` keys and `NUMBER` indices walked in one word, each step a
  `DGET` or an `NTH` on the value so far, refusing with the step that failed.
  A parsed JSON, XML or HTML document, a `CSVPAIRS` row and an HTTP header
  dict all walk with it.
- **Sparky's `put` tool** banks text in a register without passing through
  the tokenizer. A line's string ends at the first closing quote and has no
  escapes, so a JSON document, which needs double quotes, had no line that
  would carry it. `put` takes the text whole, exactly as `text "name" STO`
  would, and `"doc" RCL JSONPARSE` follows. The tape records the name and the
  length, never the text. `PUT` is registered in the dictionary for `HELP`
  and `WORDS`, beside `SAVE` and `LOAD`, and refuses with the tool's name when
  typed.
- The sparky grounding names the string trap and the way round it, and the
  [sparky page](https://shoddymills.github.io/shoddy/mills/sparky.html) says
  how to pair the server's `--root` with a Fettler tree so one tool can write
  a file the other loads.
